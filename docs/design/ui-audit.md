# UI 审计：视觉系统、页面层级与细节缺陷

日期：2026-11-10
状态：0.6.6 逐页 UI/UX 复核完成；0.5.0 的问题台账保留为历史基线。

## 1. 方法与样本

- 视口 1408×880，Chromium 通过 CDP 驱动打包后的 Electron 渲染层（`apps/desktop/dist`），真实 React 输出，非静态稿。
- 方法：`WorkspaceService` 写入确定性种子工作区（2 个项目、5 个目标，覆盖 decision / review / waiting / completed），再用空工作区补首启状态。
- 样本 21 张：注意力首页、目标列表、目标详情（决定 / 验收 / 等待）、设置、收件弹窗、侧栏折叠，各含深色与浅色；空状态首页、空目标列表、添加项目弹窗。
- 量化证据来自 `apps/desktop/src/style.css` 的 token 普查、字号普查，以及按 WCAG 2.1 公式计算的对比度。
- 设计基线见根目录 `DESIGN.md`（由 `ibelick/ui-skills@create-design-md` 生成，`design.md lint` 0 error、`export --format dtcg` 通过）。它记录**现状**，不含本审计建议的目标值。

结论先行：**结构没有大问题，问题集中在四层——深浅两套主题的质量不对等、字号系统缺层级、局部状态渲染错误、重复信息挤占注意力。**

## 4. 建议的推进顺序

1. **修 P0 的六处渲染与层级错误**（A1–A5 是纯实现问题，改动小、收益直接）。
2. **重做字号与间距 scale**，同时把浅色主题的 surface/line/muted 换掉（A6、B1、B2），这两件事必须同批做，否则旧值会不断回流。
3. **按页面收信息**：先首页与目标详情（A4、A5、B3、B6），再设置页（B7）。
4. **最后做视觉校准**：装饰、状态芯片、链接、省略号等 P2。

## 6. 0.6.6 逐页 UI/UX 复核

本轮使用已安装的 `ui-ux-pro-max` skill 完成产品系统检索、React 焦点规则核对和
页面级视觉审查。检索结果为“Teal focus + warm action”的 AI 生产力工具方向；
实现时降低饱和度并保留 Crewvane 的像素魔法师品牌，不直接采用模板色。

### 6.1 主题与语义 token

| Token | Dark | Light | 主要用途 |
| --- | --- | --- | --- |
| bg | `#0d1214` | `#f4f8f6` | 窗口与滚动区底色 |
| surface | `#172023` | `#ffffff` | 卡片、弹窗和固定栏 |
| text / secondary / muted | `#edf4f2` / `#bfd0cb` / `#96aaa5` | `#1d2a27` / `#43554f` / `#5d706a` | 三级文字 |
| accent / accent-soft | `#5ed9c9` / `#153836` | `#0d6f65` / `#def2ed` | 主操作、选中、需要人处理 |
| mint / warm / danger | `#9adba4` / `#efc56f` / `#ff9ba1` | `#2c7048` / `#8a5a19` / `#913741` | 完成、外部等待、阻塞与破坏性动作 |

关键正文和状态组合在深浅主题下的对比度为 5.10–16.90:1。主按钮悬停只在
`accent → accent-strong` 同色阶内变化，不再跳到成功绿，避免把“可点击”误解为
“已完成”。

### 6.2 页面和组件

### 6.3 自动验收

`CREWVANE_KEEP_TEST_ARTIFACTS=1 pnpm test:desktop` 在打包后的 Electron 中生成
54 张审计截图，覆盖 3 种尺寸 × 深浅主题 × 注意力、待办池顶部和两类分类、
全部目标、设置页顶部与底部、目标详情、新建目标。最终结果：

- 对比度、横向裁切、无名称按钮、小于 24px 的点击目标：0。
- 右上角管家状态与“新目标”按钮垂直中心差：0px。
- 三目标并发创建：约 47–49ms，最长主线程长任务 0ms。
- 深浅主题、侧栏折叠、图片粘贴/拖入、长文本、Webhook、现场同步、目标重启和
  待办池完整流程均通过真实打包应用回归。
