# Crewvane｜协航 使用说明

## 这是什么

Crewvane 帮你记住并行工作里的下一步。所有项目和个人事项都进入同一个工作区，由一位 Herdr 管家统筹。你只在需要决定、验收、到期跟进或会话介入时处理；普通进展不会持续打扰。

它不替代 Codex、Claude、OMP、Cursor、Qoder 等 CLI Agent。任何已经能在终端中运行的 Agent，都可以在 Herdr Session 中使用。

## 安装

从 [GitHub Releases](https://github.com/gdli6177/crewvane/releases) 下载当前版本的 `.dmg`，将 Crewvane 拖入“应用程序”；也可以使用 `.zip`。支持 macOS Apple Silicon，无需另外安装 Node。

应用未使用 Apple Developer ID 签名和公证，首次打开可能提示“无法验证开发者”。确认下载来自本项目且 SHA-256 一致后，在“系统设置 → 隐私与安全性”选择“仍要打开”。如果提示安装包“已损坏”，不要绕过，重新下载当前版本并核对校验值。

## 第一次使用

1. 首次打开 Crewvane，选择一个专用工作区目录。状态保存在该目录的 `.crewvane/`。这是全局数据的存储位置，不是项目入口；以后在“设置 > 工作区存储位置”更换。
2. 安装包内置官方 Herdr TUI CLI，首次启动无需 Homebrew、系统 PATH 或额外下载。应用启动后会通过轻量的 GitHub Releases API 检查最新版，校验资产 SHA-256 和实际可执行版本；较新的官方版本可更新到应用自己的运行目录，不修改用户已有安装。联网检查失败时继续使用应用内置或本机可用版本，并在“设置”显示更新提示和重试入口。在“设置”可查看实际路径、检查更新，并安装应用内 Crewvane CLI。
3. Herdr 就绪后，应用会自动安装并注册内置的 Crewvane 注意力插件。不需要另外运行 `herdr plugin install`；从 Herdr 的插件动作可以打开注意力控制台、直接进入一行新建目标，或回到全局管家。插件同时订阅 Herdr 原生 Agent 状态和 Pane / Tab / Workspace 生命周期事件，负责人阻塞、移动、退出或关闭现场时立即写回 Crewvane；Pane 被移动后会自动改用 Herdr 返回的新身份。桌面轮询只作为插件断线时的兜底。
4. 在“Agent 接入”检查本机 Agent。Crewvane 会自动安装已支持且格式兼容的生命周期 Hook；Codex 首次显示“等待信任”时，需要按界面提示在 `/hooks` 中审核并信任 Crewvane 条目。已有用户 Hook 会保留，停用或卸载只移除 Crewvane 管理的条目。
5. 在“Agent 启动命令”填写各角色使用的 CLI 命令，可附带模型等参数；负责人和工人留空则跟随上一级。点击“准备管家”会在后台准备该工作区唯一的 `concierge`。
6. 在“设置 → 上线策略与决定账本”确认项目策略。新项目默认外部审批；只有你可以在桌面修改。
7. 点击“新目标”，在一个输入框里直接说要做什么、知道哪些背景、怎样算完成，按“交给管家”或 `⌘ / Ctrl + Enter`。不用先选项目、流程、等待对象或提醒；完整原文和附件随目标通知发给管家，同时保存在目标中供后续读取。输入框支持粘贴截图、拖入图片或选择 PNG、JPEG、WebP、GIF，最多 8 张、单张 10 MB、总计 30 MB。保存后直接打开目标详情，可以继续补充意见、查看图片或查看派发状态。在项目页创建时自动带上当前项目，其他时候先作为个人事项保存，管家不会凭空猜项目。
8. 忙碌时关闭窗口即可；目标、提醒和 Herdr 现场会保留。

点击侧边栏的“找管家 / 回到现场”或目标里的“回到现场”打开应用内 Herdr 终端，点击“隐藏终端”即可收起；会话继续执行。打开新目标等表单时终端暂时隐藏，不会盖住正在填写的内容，也不需要打开系统 Terminal。

每个工作区有独立的 Herdr Session 与 socket。直接在外部终端运行 `herdr` 默认连接 `default`，所以看不到 Crewvane 工作区；这与用 mise、Homebrew 或应用内置二进制安装无关。设置 → Herdr 会显示当前实际 Session 名和可复制的连接命令：`herdr session attach <session>`。连入同一 Session 后再选择对应 Workspace / Tab，看到的就是同一套 Agent 现场。已结束目标的 Tab 会被关闭，不会重新出现在现场列表中。

左上角“我的工作台”回到所有项目与个人事项的总览，不会打开目录选择器。新增项目始终在左侧项目栏的“添加项目”中完成，可关联本机目录，也可只做事项归类。

在设置中更换工作区目录会切换该目录的目标与管家，并显示成功反馈。选择同一目录也会明确提示，取消选择则保留当前工作区。单个代码项目不需要单独换工作区。

Agent 启动命令允许任意本机交互式 CLI、启动脚本、`npx --yes my-agent`、绝对路径或 `~/` 路径，完整保留参数。Herdr 已识别的 CLI 使用原生 Agent 通信；自定义 CLI 直接在 Pane 中启动，以真实前台进程 ID 关联现场并发送输入。未报告生命周期时显示 `unknown`，不会伪造工作/完成状态；进程退出或被替换后拒绝向原现场发任务。环境变量、shell 管道或复杂表达式请写入自己的启动脚本，设置中填写脚本路径与参数。

Crewvane 不会替 Codex、OMP、Cursor 或其他 CLI 自动添加 `workspace-write`、网络、审批或额外目录参数。模型、沙箱和权限选项都按你填写的原生参数交给对应 CLI；实际能力由该 CLI 自己决定。

从 Finder 启动时，Crewvane 会读取用户登录 shell 的 PATH，并检查常见安装目录，不只依赖桌面进程的精简 PATH。“设置 → 打开 Herdr”可独立打开终端，即使管家启动命令有误也能查看现场；“准备管家”才会启动或恢复管家。

## Agent 即时事件

目标详情中的轻量运行状态条会显示最近一次 Hook / Extension 事件、事件时间、当前 attempt 的最新回复，以及回执提醒状态。支持 Codex、Claude Code、Cursor、Qoder 与 OMP。Hook 通过本地 Socket 送入当前应用；应用关闭时写入 `.crewvane/runtime/spool/`，重启后补处理。

Hook 只证明会话、回合、阻塞或中断发生。目标完成、等待外部、需要你决定和提交验收仍必须使用 Crewvane 现有 CLI。普通 Agent 回复、Stop、工具调用或终端 `idle` 都不会自动改变目标状态，也不会自动进入注意力。

负责人结束回合后，如果 5 秒内没有结构化写回，Crewvane 会在同一负责人现场提醒一次，列出可用的 `progress / decide / wait / review` 命令；再等 30 秒仍缺失时，只交给全局管家核对。每个回合最多提醒一次，新输入、重启和结束会取消旧提醒。Codex Hook 仍受 Codex 自身信任机制约束；配置冲突、版本变化或 Hook 被停用时，Herdr 与巡检继续兜底。

Prompt 和可用的最新回复最多保存 12,000 个 Unicode 字符，并保存原文 SHA-256；工具参数、工具输出与终端全文不入库。设置中的“Agent 接入”显示版本、能力、安装状态、Codex 等待信任、兼容问题、最近事件，并提供停用与卸载。详细协议见 [Agent Runtime Hooks](product/agent-runtime-hooks.md)。

## 注意力

注意力页只显示四类事项：

- 需要你决定的业务问题；
- 已经提交、等待查看成果和检查记录的交付；
- 到了跟进时间的等待事项；
- 项目上线策略要求你审批，或需要执行九类高风险动作；
- 会话卡点先交给管家核查；无法联系管家或长期没有恢复进展时，才请你介入。

普通进展、终端空闲和 Agent 工作结束不会进入注意力。Herdr 的 `done` 只表示会话空闲，不能代替成果验收。

应用默认发送 macOS 系统通知。你也可以在设置中配置 HTTPS Webhook（本机 localhost 可用 HTTP，可选 Bearer 令牌）；事项首次进入注意力时 POST 一次，成功投递跨重启去重，失败 5 分钟后重试。载荷只含工作区名称、目标标题、状态、摘要和 `goalId`，不含聊天历史、附件或本机路径。Webhook 暂时失败不会改变目标，也不会阻止收件箱操作。详见 [消息通知](product/notifications.md)。

“等待外部”只用于用户和所有 Agent 之外的联系人或机构，例如等 YR 审批、等供应商交货；需要你决定、确认、提供信息或操作时进入注意力，内部 Agent 协调保持跟进中。你只需输入一句话，例如「审批已通过，可以继续」「仍在等，明天再看」或「这件事结束吧」，然后点击「交给管家」。外部等待交回管家核查时先恢复跟进中、清除旧等待与提醒，保留原下一步；管家读取原话和历史等待记录后重新确认安排。未解决的决定、验收和介入不会被普通留言清除。「1 小时后提醒」只修改提醒时间，不改变生命周期。消息区分正在发送、已送达和失败可重试，应用重启后保留尚未发送的更新。

## 目标与验收

默认导航采用场景优先：真实现场介入与有已登记现场的普通活动目标直接打开 Herdr；需要决定、验收、到期跟进和派发失败时，打开只含当前依据与动作的轻量卡片。顶部“回到现场”仍可随时进入真实终端；卡片底部“完整记录”保留目标背景、消息历史、附件与目标管理。等待中、未建立现场和已结束目标仍直接打开完整记录。

现场上方的目标条显示项目、状态和结构化当前事项，可以“回到注意力”或打开“目标记录”。终端滚动历史留在 Herdr，不自动复制进目标上下文，也不能代替真实验收证据。负责人提交验收时必须写入成果摘要，以及至少一项真实执行过的检查命令或操作。Crewvane 不接受空的或失败的检查记录。

如果你想自己处理一个正在推进的新目标，点详情里的“我来处理”。它会停止后续自动派发，即使此前已经有一条发送请求正在处理，迟到的回执也不会重新把目标交给管家。之后改变主意时，点“交给管家”会建立一条新的派发请求。

进行中的事项想提新要求或约束，直接在详情里的“给管家留言”写一句，点“交给管家”。意见作为原始消息追加到动态并通知管家，保留原下一步；外部等待交回 Agent 时先恢复跟进中，待管家核定。待验收事项仍可明确“验收通过”或“退回修改”。文本本身不会被 core 按关键词自动当成批准、验收或完成。

目标详情的“目标消息与交接记录”完整展示用户原话、管家 / 负责人具体答复和系统事件，不只显示最近几条。执行 Agent 回答咨询时必须写回答案正文、依据和下一步；Crewvane 会拒绝只包含「已回答」「已回复」等占位词的 Agent 进展或成果摘要。自由消息与状态命令分开保存，所以插件或 CLI 不能借“补充意见”偷偷改下一步。

目标里的图片会保留缩略图与原图入口。点击图片可打开原图，垃圾桶按钮会同时删除文件与目标中的元数据。进行中的目标不会自动删除图片；已验收或放弃的目标默认保留原图 30 天，应用下次启动时清理。

「手动处理」只用于自行接管或纠正：补充进展只记录已经发生的事实，不改变原定的下一步；编辑目标修改目标说明、下一步、等待对象和提醒；提交成果附实际成果与检查，进入待验收。结束等待、请管家核查或稍后提醒请用等待区域的直接操作，不必理解这些高级表单。

“验收通过”会结束目标并清除它的注意力；“退回修改”会把原因写回目标和时间线。验收通过本身不会替负责人合并代码、发布应用或发送外部消息；这些外部动作必须先按项目上线策略取得授权。

已完成或已放弃的目标可以永久删除，删除时会一并清理它的图片。Herdr 可用时，负责人 Tab 会在目标完成、放弃或删除时自动关闭；Herdr 暂时不可达时保留现场引用，巡检恢复后自动重试关闭，期间永久删除会失败，可等现场关闭后再次删除。

## 上线策略与决定账本

每个项目有三种上线策略：`external-approval`、`auto-merge-manual-deploy`、`auto`。默认 `external-approval`：即使检查和审查通过，合并与部署也需要你在桌面确认；设置中的审批人目前仅作展示，不做身份校验。第二种策略自动合并，但部署前仍需确认。`auto` 在真实检查通过后可放行合并与部署。Crewvane 本身不执行 Git、部署或外发，只给负责人返回是否已经得到项目策略授权。

你批准或拒绝后，原话、时间、来源、项目和目标会写入 `.crewvane/decisions.md` 或 `.crewvane/rejected.md`。后续同类问题按稳定动作键命中账本，不再反复进入注意力。需要推翻旧决定时，就针对新决定再次明确回复。

删除数据、停服、花钱、向外部人员发消息、改变产品方向、新建或轮换密钥、修改权限、修改上线策略，这九类动作始终先问你，项目设为 `auto` 也不例外。Agent 不能通过受管 CLI 修改项目策略。这是 core 的应用层协议约束，不是操作系统沙箱；第三方 Agent 的文件与网络权限仍由它自己的 CLI 决定。

同一目标最多提交三轮审查。需要第四轮时，Crewvane 拦截提交并进入注意力；你允许后再增加一轮。审查报告只接受会导致错误的问题，风格建议不占用轮次。

## 管家

一个工作区只有一位管家，所有项目都找它。Crewvane 负责准备持久 Session、复用已有管家并给新目标发送提醒；目标、负责人和 Tab 拓扑由管家按照实际情况组织。

同一工作区的多个目标会严格排队进入管家，每条消息只包含一个案卷和唯一 ID，管家不能通过受管 CLI 列出或修改其他目标。这个应用层案卷闸门降低串案风险，但不伪装成操作系统文件沙箱；任意第三方 Agent 仍受其自身权限机制约束。

你也可以直接在 Herdr 里对管家追加要求。Herdr 0.9.5 没有把用户提交的 prompt 暴露给插件的钩子，因此不能从终端字节流可靠反推你刚发了什么；产品约定是管家收到终端直聊后，先执行 `crewvane direct --current "<原话>"` 追加到当前案卷，或用 `crewvane direct --new "<原话>"` 建立新目标，再继续处理。新目标写回后会自动成为管家当前的案卷 scope，因此同一回合还能继续整理和派发。CLI 写回后桌面会监听同一工作区并刷新，不再重复派发这条已经送到管家的消息。若管家没有执行这条写回，普通聊天内容只留在终端，不会出现在 App；可靠的一行新建入口仍是 Herdr 插件的“给 Crewvane 新建目标”或桌面“新目标”。

Herdr 事件只更新已经保存在目标中的同一 Pane 现场。插件事件本身没有创建目标、验收或发布权限，也不会因为某个 Agent 进入 `done` 就宣称目标完成。`done` / `idle` 仍需负责人通过交付记录提交真实成果与检查，人工验收仍由人完成。

管家只负责分发、协调跟进和向你交接，不亲自执行目标，简单任务也交给独立负责人。它读取目标、完整原文和项目规则，创建或复用负责人，转达任务与退回原因，并维护下一步、等待和提醒。开发、设计、测试等具体流程由任务原文、项目规则或对应 Agent skill 提供，不是所有目标都要填写的产品字段。

一个 Herdr Session 中保留一位全局管家，两个执行目标应各有独立的负责人 Tab。目标详情区分「已通知管家，等待分配负责人」与真实负责人现场的登记和连接，通知送达不表示已经开始执行。超过一分钟尚无负责人现场时，巡检先请管家补充分发；仍未恢复或联系失败时才请求人介入。等待他人或等待你决定的事项不强制创建执行会话。

负责人负责实际产出、执行检查并提交交付。管家核对成果位置和检查记录是否齐备，缺失则交回补齐，齐备后通过注意力交给你验收；不会代写成果、代跑测试或替你验收。负责人遇到问题时，管家先澄清要求、调整分工或联系其他负责人，协调仍无法解决才向你请求决定。

## CLI

设置页会把完整 CLI 安装到当前应用的 userData 目录，并在 `~/.local/bin/crewvane` 建立符号链接。它使用应用自带的 Node runtime，不依赖用户安装 Node。

```sh
crewvane status --root /path/to/workspace --json
crewvane attention --root /path/to/workspace --json
crewvane board --root /path/to/workspace
crewvane ask "检查发布流程并补齐证据"
crewvane ask "按截图修复布局" --attachment ~/Desktop/before.png --attachment ~/Desktop/after.png
HERDR_PLUGIN_EVENT_JSON='…' crewvane event herdr --json
crewvane goal list --root /path/to/workspace --json
crewvane goal show <ID> --root /path/to/workspace --json
crewvane goal message <ID> --text "增加回滚验证"
crewvane direct --current "补充背景，不改下一步"
crewvane goal progress <ID> --summary "完成实际步骤" --next "下一步"
crewvane goal wait <ID> --reason "等待审批" --owner YR --remind-at 2026-11-05T10:00:00+08:00
crewvane goal risk <ID> --category delete-data --summary "删除生产数据库"
crewvane goal ship <ID> --operation deploy --checks passed
crewvane goal review <ID> --summary "实际成果" --check "回归测试::pnpm test::passed::全部通过"
crewvane goal resolve <ID> --note "批准今天发布" --outcome approved
```

`CREWVANE_WORKSPACE=/path/to/workspace` 可以替代 `--root`。桌面和 CLI 使用同一把锁，不会覆盖彼此的并发修改。`goal message` 与 `direct` 是消息入口，只追加原话和附件；`progress`、`wait`、`review`、`decide` 等是 Agent 或受信任适配器在明确事实发生后使用的高级状态协议。`direct` 不接受 `--next`。

`crewvane board` 是 Herdr 注意力插件使用的终端控制台；可直接处理决定、等待推进、人工接管、验收与退回，按 `g` 可回到全局管家。桌面未运行时，`ask`、消息、决定和跟进仍会保存为待派发请求，下一次启动桌面后继续发送。

## 数据与限制

工作区目标保存在 `.crewvane/state.json`，事件保存在 `.crewvane/events.jsonl`，决定账本在 `.crewvane/decisions.md` 与 `.crewvane/rejected.md`。这些是本地数据，不会被 Crewvane 上传。模型登录、权限和网络访问仍由 Herdr 中的各个 Agent CLI 管理。

图片原图保存在 `.crewvane/attachments/`。状态与分析事件只记录文件名、相对路径、大小、MIME 和 SHA-256，不保存 Base64 或图片字节。导入会检查真实文件魔数、数量与大小；目标详情可以立即逐张删除，已结束目标默认保留 30 天，应用启动时清理，失败留下的无引用文件也会在过期后回收。

Crewvane 本身不执行 Git、部署或外部消息；负责人必须先用 `goal ship` 取得项目策略授权。它不会把终端状态、Agent 自述或模型推断当成成果完成，也不会让自动策略绕过九类高风险动作。

## 故障排查

- “Herdr 会话未能启动”：检查设置中的实际 Herdr 路径与错误，重试自动准备；通过“设置 → 打开 Herdr”查看现场错误。
- 已安装 Herdr 桌面 App 仍缺少 CLI：Crewvane 需要 Herdr TUI 的 `herdr` 命令，应用会自动准备，不要求用户另外安装 Homebrew。不会改动已有桌面 App 或其他 Herdr 安装。
- 重复点“准备管家”不会创建新管家；应用会优先复用实时 `concierge`。
- 移动或删除 Crewvane 应用后，`~/.local/bin/crewvane` 可能失效。重新安装应用并在设置中重新安装 CLI。
- 工作区被占用时会显示锁文件和持有进程，不会强行覆盖仍在写入的状态。
- 安装应用提示“已损坏”时，核对 GitHub Release 来源和 SHA-256，再下载同版本附件；不要用清除隔离属性掩盖损坏的包。
