# 安装与 GitHub Releases 交付

版本发布后，从 [GitHub Releases](https://github.com/gdli6177/crewvane/releases) 进入对应版本，在 **Assets** 下载。当前只支持 Apple Silicon Mac（arm64），不提供 Intel Mac、Windows 或 Linux 安装包。

| 附件 | 使用方法 |
| --- | --- |
| `Crewvane-<version>-macOS-arm64.dmg` | 打开磁盘映像，将 Crewvane.app 拖入 Applications，然后从“应用程序”打开 |
| `Crewvane-<version>-macOS-arm64.zip` | 解压后将 Crewvane.app 移入“应用程序” |
| `SHA256SUMS.txt` | 执行 `shasum -a 256 -c SHA256SUMS.txt` 核对安装附件 |

GitHub 自动生成的 **Source code** 是源码，不是可安装应用。安装包自带 Electron、CLI runtime 和经 SHA-256 校验的 Herdr TUI CLI，无需安装 Node、pnpm 或 Homebrew。Agent CLI 仍由用户自行安装和登录。

当前包没有 Apple Developer ID 签名与公证，首次打开可能出现“无法验证开发者”。核对发布来源与 SHA-256 后，可在“系统设置 → 隐私与安全性”选择“仍要打开”。如果出现“已损坏，无法打开”，不要清除隔离属性绕过；重新下载当前版本并联系维护者。`v0.3.0` 的签名不完整，不应继续使用。

安装替换应用后，打开设置重新安装 Crewvane CLI，确保 `~/.local/bin/crewvane` 指向当前应用。工作区位于用户选择的目录，不会被覆盖。

## 0.6.5 安装与验收

0.6.5 修复负责人 Agent 已经停止输出、目标却仍显示为持续执行的问题。Herdr 的 `idle` / `done` 现在只表示负责人当前停下，不会自动把目标判为完成或失败。负责人持续静默 90 秒且没有写回结果时，目标显示“待管家核对”，巡检先联系唯一管家，再由管家联系原负责人补齐真实结果、下一步、决定或交付；管家不可达或 10 分钟后仍无恢复时才升级给人。运行中的 OMP 等 CLI 若仍报告 `idle`，终端标题 spinner 会被识别为 `working`，避免工具执行期间误触发核对。

活动目标不再统一显示为“进行中”。界面分别展示“执行中”“待管家核对”“管家核对中”“待管家跟进”和“待分配”，`active` 只表示仍需跟进。负责人启动命令、环境初始化和长消息也按终端输入上限安全拆分；启动失败会写回真实原因和下一步。本次同时包含现场答复回执与轻量待办池：暂存事项不派发、不巡检，个人事项可以直接完成。

1. 安装 DMG 或 ZIP 后，在设置中重新安装 Crewvane CLI。
2. 让负责人在终端完成一个阶段后直接停下，不调用 Crewvane 状态命令。约 90 秒后确认目标从“执行中”变为“待管家核对/管家核对中”，不会直接进入人工注意力，也不会被标成完成。
3. 确认管家联系原负责人后，目标收到负责人写回的决定、等待或交付；只有真正需要人时才出现在注意力面板。
4. 新建一条“先记下”的事项，确认不会启动 Agent 或产生巡检；将其开始或交给管家后，原记录、附件和历史保持不变。

## 0.6.4 安装与验收

0.6.4 修复内嵌 Herdr 显示“copied to clipboard”，但 macOS 系统剪贴板没有更新、离开 Crewvane 后无法粘贴的问题。Herdr 在鼠标捕获模式下通过 OSC 52 写入剪贴板；iTerm2 等宿主终端原生支持该协议，旧版内嵌终端没有处理。现在 Crewvane 将 OSC 52 写入接到 macOS 系统剪贴板，同时拒绝 OSC 52 读取，避免终端程序读取宿主剪贴板。0.6.3 加入的 `⌥` 拖动选择路径已移除，普通拖动即可自动复制。设置中的 Herdr 卡片会显示当前命名 Session，并提供“复制命令”，方便在 iTerm2 等外部终端 attach 到同一现场；裸跑 `herdr` 仍连接独立的 default Session。

等待与到点跟进不再提供“补充情况 / 让管家跟进 / 有结果继续推进”三个语义重叠的按钮，只保留“告诉管家”自由输入框和“1 小时后提醒”。发出一条消息后，该次提醒会离开注意力队列，但目标保持等待；唯一的全局管家读取完整原话后决定继续等待、恢复推进、验收、完成或放弃。管家执行结束或决定时只能在当前案卷内操作，并必须保存用户明确说出的原话。

1. 安装 DMG 或 ZIP 后，在设置中重新安装 Crewvane CLI。
2. 打开真实 Herdr 现场，普通拖动一段终端文本；看到 Herdr 的复制提示和 Crewvane 的“已复制 N 个字符”后，在 Crewvane 外部应用执行 `⌘V`，确认内容正确。
3. 将一条目标设置为已到期的跟进提醒，确认只出现“告诉管家”输入框和“1 小时后提醒”。输入“还在等”或“已经完成”并提交，确认消息离开注意力、目标状态在管家写回前保持不变，Herdr 管家实际收到原话。

## 0.6.3 安装与验收

0.6.3 修复 Herdr 开启鼠标上报后无法从现场复制文本的问题。普通拖动会作为 Herdr 鼠标操作发送，不会在 xterm 中建立选区；现在按住 `⌥` 拖动可以强制选择文本，现场标题会显示该提示。选中后可使用 `⌘C` 或标题栏复制按钮，并显示复制字符数。

1. 安装 DMG 或 ZIP 后，在设置中重新安装 Crewvane CLI。
2. 打开一个真实 Herdr 现场，在终端文本上普通拖动，确认 Herdr 仍能接收鼠标操作。
3. 按住 `⌥` 拖动选择一段文本，使用 `⌘C` 后粘贴到 Crewvane 外部应用，确认剪贴板内容正确。
4. 再次按住 `⌥` 拖动选择文本，使用现场标题栏的复制按钮，确认出现“已复制 N 个字符”反馈且外部粘贴正确。

## 0.6.2 安装与验收

0.6.2 修复到期跟进 Webhook 在通知已发送后重复投递的问题。`follow_up` 的 delivery id 使用 `goalId`、`kind` 与 `remindAt`，不再随 `attention.since` 变化。设置中的高风险说明包含「修改上线策略」，与后端 9 类一致。说明文档与当前实现一致：九类高风险动作由 core 做协议约束，不是操作系统沙箱；审查按目标计数；审批人只展示；附件在目标结束后按保留期清理；永久删除与关闭 Tab 失败后可以重试。`install.sh`、adapters、events schema 与 `ship-*` 技能标为 legacy。

1. 安装 DMG 或 ZIP 后，在设置中重新安装 Crewvane CLI。
2. 将目标设为到期跟进并配置 Webhook。到点后应只收到一次 `follow_up`；应用记录 `notification.sent` 后，同一提醒不应再次 POST。
3. 打开设置中的高风险说明，确认包含「修改上线策略」。

## 0.6.1 安装与验收

0.6.1 修复合法长文本目标被错误拒绝的问题。正文仍允许最多 20,000 字；列表标题改为从首个非空行生成并最多保留 80 个 Unicode 字符，不再先用 160 字上限校验整段单行正文。新建目标与 Herdr 直聊使用同一规则。

1. 安装 DMG 或 ZIP 后，在设置中重新安装 Crewvane CLI。
2. 在“把这件事交给我”中提交一段超过 160 字、且第一行也没有换行的目标，确认目标可以创建，标题显示前 80 个字符，详情中完整正文没有截断。
3. 用 `crewvane ask` 或 Herdr 直聊提交同类长文本，确认得到相同的标题和完整正文。

## 0.6.0 安装与验收

0.6.0 只提供 Apple Silicon Mac（arm64）安装包。打开旧版、损坏或缺快照的工作区时，Crewvane 会先完整归档原 `.crewvane` 为相邻的 `.crewvane.backup-*`，再自动创建兼容的新工作区，并在应用内显示归档位置；旧执行状态、审批和 Herdr 现场不会被猜测恢复。此版本仍未进行 Apple Developer ID 签名与公证，下载和首次打开时按上文的来源、SHA-256 与隐私安全提示处理。

1. 安装 DMG 或 ZIP 后，在设置中重新安装 Crewvane CLI，并按需安装或更新 Crewvane Skills。
2. 从“注意力”打开需要决定或验收的目标：使用轻量卡片完成操作；选择“完整记录”可查看消息、附件和目标管理。
3. 点击普通活动目标或真实会话介入事项，确认直接进入真实 Herdr 现场。顶部目标条可返回注意力或查看目标记录；隐藏终端不会关闭 Agent 会话。
4. 到期跟进和派发失败仍在卡片内处理；已结束目标只打开历史记录，不重新打开已经关闭的现场。
5. 确认目标说明、下一步和验收事实仍来自结构化 Crewvane 记录。现场原文用于操作与核对，不会自动注入 Agent 上下文或被当作验收依据。
6. 如需验证升级保护，可选择旧版状态目录。应用应显示“旧版工作区已自动保护”，原文件应完整存在于显示的 `.crewvane.backup-*` 目录中，新工作区可以正常创建目标。

## 0.5.2 安装与验收

0.5.2 只提供 Apple Silicon Mac（arm64）安装包，没有旧版工作区兼容层；首次使用请选择新目录。此版本仍未进行 Apple Developer ID 签名与公证，下载和首次打开时按上文的来源、SHA-256 与隐私安全提示处理。

1. 安装 DMG 或 ZIP 后，在设置中重新安装 Crewvane CLI。
2. 在“让外部 Agent 会使用 Crewvane”中安装或更新 Skills，并确认检测到的目标目录显示为已安装。已有同名且非 Crewvane 管理的 Skill 会被保留。
3. 打开真实 Herdr 现场，确认终端可拖动、调整大小、全屏、隐藏，并可用系统剪贴板复制粘贴。移动或关闭 Pane 后，Crewvane 应更新现场身份与可达状态。
4. 在终端里与 Agent 对话后，确认目标语义仍需 Agent 用 Crewvane CLI 显式写回；终端输出不会自动生成消息、进展或验收结果。
5. 配置企业微信 Webhook，将同一目标进入待验收，确认只收到一条 `attention.required` 消息，不再同时收到 `goal.status_changed`。
6. 从注意力打开决定、验收和到点跟进目标，确认当前依据、主操作与完整对话在同一弹窗内可见；1024×720、深色和浅色布局均无横向溢出。
7. 点击左上角“我的工作台”，确认当前工作台首页有明确选中态；在目标管理中选择“放弃目标”，确认会打开应用内原因输入并成功记录，而不是点击无反应。

## 本地制作与验收

在 macOS arm64 上执行：

```sh
pnpm install --frozen-lockfile
pnpm desktop:dist
pnpm test:installers
```

附件输出到 `apps/desktop/release/installers/`。验收会核对 SHA-256、磁盘映像、ZIP 解压、DMG 复制、完整代码签名和下载隔离属性，然后启动两种安装结果，确认新界面、renderer 隔离、图标元数据，并安装包内 CLI 实际创建目标。它不需要模型账号；Herdr 闭环另由桌面 E2E 与真实隔离 Session 试用覆盖。

## 维护者发布步骤

1. PR 的 **Desktop installers** 工作流执行类型检查、测试、打包与安装验收。
2. 合并前确认真实试用记录和所有未解决风险。
3. 根目录和桌面包版本一致后，创建并推送完全匹配的标签，例如 `v<version>`。
4. 标签工作流重跑验收，再创建包含 DMG、ZIP、SHA256SUMS 和说明的 prerelease 草稿。
5. 检查附件与说明后发布。发布后真实下载所有附件，核对 SHA-256，并在一台独立 Mac 上启动应用和安装 CLI。

标签工作流不合并 PR，也不自动公开 Release。
