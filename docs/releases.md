# 安装与 GitHub Releases 交付

版本发布后，从 [GitHub Releases](https://github.com/gdli6177/crewvane/releases) 进入对应版本，在 **Assets** 下载。当前只支持 Apple Silicon Mac（arm64），不提供 Intel Mac、Windows 或 Linux 安装包。

| 附件 | 使用方法 |
| --- | --- |
| `Crewvane-<version>-macOS-arm64.dmg` | 打开磁盘映像，将 Crewvane.app 拖入 Applications，然后从“应用程序”打开 |
| `Crewvane-<version>-macOS-arm64.zip` | 解压后将 Crewvane.app 移入“应用程序” |
| `SHA256SUMS.txt` | 执行 `shasum -a 256 -c SHA256SUMS.txt` 核对安装附件 |

GitHub 自动生成的 **Source code** 是源码，不是可安装应用。安装包自带 Electron、CLI runtime 和经 SHA-256 校验的 Herdr TUI CLI，无需安装 Node、pnpm 或 Homebrew。Agent CLI 仍由用户自行安装和登录。

当前包没有 Apple Developer ID 签名与公证，首次打开可能出现“无法验证开发者”。核对发布来源与 SHA-256 后，可在“系统设置 → 隐私与安全性”选择“仍要打开”。如果出现“已损坏，无法打开”，不要清除隔离属性绕过；重新下载当前版本并联系维护者。`v0.3.0` 的签名不完整，不应继续使用。

安装替换应用后，打开设置重新安装 Crewvane CLI，确保 `~/.local/bin/crewvane` 指向当前应用。工作区位于用户选择的目录，不会被覆盖。

## 0.7.1 安装与验收

0.7.1 修复“负责人已写回本轮结果、管家正常空闲，但目标仍显示待核对”的展示错误。列表与详情现在共用同一运行事实映射，不再单凭 `idle` / `done` 或旧 `recovery` 提示推断存在核对任务。

| 真实事实 | 显示 |
| --- | --- |
| 当前回合已通过 Crewvane CLI 写回，现场没有继续执行 | 本轮已回报 |
| 负责人仅处于空闲，尚无核对请求 | 负责人空闲 |
| 已持久记录核对请求，尚未确认送达 | 待管家核对 |
| 核对请求已送达，尚未有新处理结果 | 已请管家核对 |
| 现场答复已保存但尚未送达管家 | 现场答复待同步 |

需要人决定、验收、到期跟进或介入的明确事项优先于运行标签。界面不解析“下一步”文字猜测注意力，也不把本轮回报当作整个目标完成。真实的 30 分钟无业务进展巡检仍会触发，不能被上一轮回报永久屏蔽。

本版同时修复回执提醒可能只让 Herdr API 返回成功、却没有把提醒真正送入负责人输入框的问题。提醒改为单个逻辑行，并通过 `agent prompt --wait --until working` 确认同一个负责人实际进入处理；多行输入短暂出现在输入框、但未提交的情况不再被误判为送达。负责人仍在工作、Pane 已更换、终端未就绪或 5 秒内没有确认开始时不会重复发送，而是交给管家核对。

内嵌 Herdr 的系统剪贴板粘贴也已修复。终端现在同时处理 `⌘V`、`Ctrl+V` 和 Electron 原生粘贴事件，覆盖键盘快捷键与应用菜单两条路径；粘贴内容仍通过 xterm 的 bracketed paste 写入真实 PTY，不会复制成独立输入框。

1. 安装后确认设置显示 0.7.1，重新安装 Crewvane CLI。
2. 负责人实际执行 `goal progress` 后结束本轮，确认列表与详情均显示“本轮已回报”，详情保留实际结果和下一步。
3. 未写回且尚未触发巡检的空闲负责人显示“负责人空闲”；生成真实核对请求后才显示“待管家核对”，送达后显示“已请管家核对”。
4. 让负责人通过 `goal decide` 请求用户提供资料或操作，确认仍进入注意力，不会被空闲或上一轮已回报遮盖。
5. 从 Crewvane 外部复制一段文本，分别用 `⌘V`、`Ctrl+V` 和应用编辑菜单粘贴到内嵌 Herdr，确认文字进入当前 Agent / Shell 输入并可以正常提交。
6. 核对深浅主题、目标列表、详情与真实 Agent 现场；DMG / ZIP 均重新执行安装、签名及内置 CLI 验收。

当前安装包仍使用完整 ad-hoc 签名，未进行 Apple 公证。升级保留有效 v2 工作区、目标和会话数据。

## 0.7.0 安装与验收

0.7.0 增加 Agent Runtime Adapter 与受管生命周期 Hook。Crewvane 会检测 Codex、Claude Code、Cursor、Qoder 和 OMP；前四类使用各 Agent 官方 Hook 配置，OMP 使用官方 Extension API。安装只增删 Crewvane 管理的条目，已有用户 Hook、其他 OMP extension 和未知配置结构保持不变。Codex 仍要求在 `/hooks` 中信任新条目；设置中的“等待信任”不会被 Crewvane 绕过。

修复后台派发或注意力更新清空正在编辑的留言和图片的问题；批准、拒绝等操作仍按独立注意力事项隔离。
即时 Hook 更新保留已打开的内嵌现场，避免生命周期事件重置终端面板。

Hook 通过短路径本地 Socket 立即送入目标；应用未运行时，事件写入 `.crewvane/runtime/spool/`，使用 `0600` 权限、最多 200 条并保留 7 天。重复事件、旧 attempt、旧 turn 和乱序事件不会覆盖当前状态。Hook 只记录会话、回合、阻塞和可用的 Agent 回复，不保存工具参数、工具输出或终端全文；Prompt 与回复最多保存 12,000 个 Unicode 字符，并保存原文 SHA-256。

目标回合结束后 5 秒仍未收到 `progress`、`wait`、`review`、`decide` 等结构化写回时，Crewvane 向同一负责人提醒一次；再等 30 秒仍缺失时只交给管家核对，不会直接把 Stop 显示成完成、失败或人工待办。每个 turn 最多提醒一次。Herdr 生命周期和原有 90 秒巡检继续作为 Hook 不可用时的兜底。

1. 安装 DMG 或 ZIP 后，在设置中重新安装 Crewvane CLI，并检查“Agent 接入”。
2. 对已安装的受支持 Agent 确认显示“已接入”。Codex 首次显示“等待信任”时，按界面说明在 Codex `/hooks` 中审核并信任 Crewvane 条目。
3. 启动一个真实负责人，确认目标详情的运行状态条先显示即时生命周期事件；Hook 正常时，Stop 后约 5 秒出现一次回执提醒，负责人用现有 Crewvane CLI 写回后提示消失。
4. 让负责人结束回合但不写回，确认 30 秒后目标只进入“交给管家核对”，不会直接标成完成或失败，也不会生成人工注意力。
5. 关闭应用后触发一次受管 Agent Hook，再启动应用，确认离线队列补处理且没有重复事件；在设置中停用一个 Adapter，确认该 Agent 的目标继续由 Herdr 与巡检状态兜底。

当前安装包仍使用完整 ad-hoc 签名，没有 Apple Developer ID 签名与公证。首次打开可能提示“无法验证开发者”；出现“已损坏”时应重新下载，不要绕过 Gatekeeper。

## 0.6.7 安装与验收

0.6.7 修复执行日志中的长期可靠性缺陷。`events.jsonl` 不再为每条事件重复写入完整工作区快照，历史日志达到 16 MB 后会原子压缩到最近约 4 MB、最多 2,000 条完整事件，避免 15,000 条事件增长到数 GB。管家案卷 scope 改为临时文件加 rename 的原子替换，准备管家时不再先删除 scope，减少派发期间误判“没有当前案卷”的窗口。

负责人启动遇到 Herdr `agent_pane_busy` 时，会在同一个 Pane 上按指数退避重试，最长 15 秒；不会再连续新建多个 Pane。Herdr prompt 返回 `timeout` 或 `agent_prompt_stalled` 时，任务保存为“已提交，等待现场确认”，不再显示成“联系管家失败”，也不会自动重发可能已经送达的内容。巡检升级到人时会带上目标标题、卡点原因和最后一条真实进展，不再只显示“10 分钟无进展”。设置页新增“缓存与本地维护”：每日后台清理 30 天未用的渲染缓存与日志、退出后遗留超过 24 小时的临时文件，也可立即查看和清理当前缓存；不会碰目标、附件、Agent 会话或旧工作区备份。

1. 安装 DMG 或 ZIP 后，在设置中重新安装 Crewvane CLI。
2. 连续创建多个需要启动负责人的目标，确认启动过程中即使 Pane 短暂忙，也复用同一个 Pane 并最终写入真实现场。
3. 让 Herdr `agent prompt` 状态确认超时，确认目标显示“已提交，等待现场确认”，不会生成“联系管家失败”的注意力项，也不会自动重复发送。
4. 在大型旧工作区中触发一次状态更新，确认 `.crewvane/events.jsonl` 被压缩且仍保留最近完整事件；`state.json` 与目标历史可正常读取。
5. 制造一次巡检升级，确认注意力中的拦截项包含具体目标、卡点原因和最后进展。
6. 打开“设置 → 缓存与本地维护”，确认显示缓存占用；执行“清理缓存”后只减少缓存和遗留临时文件，目标与附件仍可正常打开。

报告中的模型侧 `Retry deadline exceeded`、未安装 Codex CLI 和命令行人工快速重试不属于本次 Crewvane 派发缺陷：前者由所用 Agent CLI 的模型重试预算产生，后两者分别是配置和操作问题。

## 0.6.6 安装与验收

0.6.6 修正目标状态的语义边界：“等待外部”只用于等待人和 Agent 之外的真实第三方。需要你决定、Agent 仍在协调或内部交接的事项不会再被归入外部等待。侧边栏待办池会直接显示“先记下”和“我来做”的未结束事项总数。

已完成或已放弃的管家目标现在可以重启。用户在目标详情中写一条给管家的说明后，目标会保留原消息、附件和事件历史并重新进入 `active`。如果结束前 Herdr 提供了负责人的真实 Agent 会话标识，Crewvane 会用该 CLI 的原生恢复参数在新 Tab 中恢复原负责人，再重新绑定现场并交给唯一管家；没有可恢复标识时明确启动新负责人。顶部栏也改为固定，长页面只滚动正文内容。

本版同时完成一次逐页 UI/UX 复核：主题从靛蓝调整为更克制的墨青与海沫青，暖琥珀承担外部等待和恢复提示；深浅主题的正文、状态文字、主按钮与柔底均通过 WCAG AA 对比度审计。注意力、待办池、全部目标、设置、目标详情和新建目标重新收敛信息层级，补充跳转主内容、可见键盘焦点、当前导航、可访问计数与折叠侧栏状态。右上角管家状态标签改用独立 CSS 命名空间，修复 `error` / `ready` 与通用状态样式碰撞造成的纵向错位。macOS 应用图标换成像素魔法师的现代简化版，保留偏斜兜帽、双眼和薄荷流带，去掉星环、全身细节和像素网格。

1. 安装 DMG 或 ZIP 后，在设置中重新安装 Crewvane CLI。
2. 新建一条“先记下”和一条“我来做”，确认侧边栏待办池数量为 2；完成、移出或恢复后确认数量立即更新。
3. 完成一个管家目标，在详情中点击“重启目标”，写一条新的推进说明；确认状态回到进行中、历史仍可见，并优先恢复原负责人会话。
4. 打开较长的设置页或目标列表滚动到底部，确认顶部栏、当前页面和“新目标”按钮始终固定在窗口顶部。
5. 让管家处于离线、恢复、工作、空闲等状态，确认右上角状态标签与“新目标”始终在同一条水平线上；切换深浅主题后布局不应跳动。

## 0.6.5 安装与验收

0.6.5 修复负责人 Agent 已经停止输出、目标却仍显示为持续执行的问题。Herdr 的 `idle` / `done` 现在只表示负责人当前停下，不会自动把目标判为完成或失败。负责人持续静默 90 秒且没有写回结果时，目标显示“待管家核对”，巡检先联系唯一管家，再由管家联系原负责人补齐真实结果、下一步、决定或交付；管家不可达或 10 分钟后仍无恢复时才升级给人。运行中的 OMP 等 CLI 若仍报告 `idle`，终端标题 spinner 会被识别为 `working`，避免工具执行期间误触发核对。

活动目标不再统一显示为“进行中”。界面分别展示“执行中”“待管家核对”“管家核对中”“待管家跟进”和“待分配”，`active` 只表示仍需跟进。负责人启动命令、环境初始化和长消息也按终端输入上限安全拆分；启动失败会写回真实原因和下一步。本次同时包含现场答复回执与轻量待办池：暂存事项不派发、不巡检，个人事项可以直接完成。

1. 安装 DMG 或 ZIP 后，在设置中重新安装 Crewvane CLI。
2. 让负责人在终端完成一个阶段后直接停下，不调用 Crewvane 状态命令。约 90 秒后确认目标从“执行中”变为“待管家核对/管家核对中”，不会直接进入人工注意力，也不会被标成完成。
3. 确认管家联系原负责人后，目标收到负责人写回的决定、等待或交付；只有真正需要人时才出现在注意力面板。
4. 新建一条“先记下”的事项，确认不会启动 Agent 或产生巡检；将其开始或交给管家后，原记录、附件和历史保持不变。

## 0.6.4 安装与验收

0.6.4 修复内嵌 Herdr 显示“copied to clipboard”，但 macOS 系统剪贴板没有更新、离开 Crewvane 后无法粘贴的问题。Herdr 在鼠标捕获模式下通过 OSC 52 写入剪贴板；iTerm2 等宿主终端原生支持该协议，旧版内嵌终端没有处理。现在 Crewvane 将 OSC 52 写入接到 macOS 系统剪贴板，同时拒绝 OSC 52 读取，避免终端程序读取宿主剪贴板。0.6.3 加入的 `⌥` 拖动选择路径已移除，普通拖动即可自动复制。设置中的 Herdr 卡片会显示当前命名 Session，并提供“复制命令”，方便在 iTerm2 等外部终端 attach 到同一现场；裸跑 `herdr` 仍连接独立的 default Session。

等待与到点跟进不再提供“补充情况 / 让管家跟进 / 有结果继续推进”三个语义重叠的按钮，只保留“告诉管家”自由输入框和“1 小时后提醒”。发出一条消息后，该次提醒会离开注意力队列，但目标保持等待；唯一的全局管家读取完整原话后决定继续等待、恢复推进、验收、完成或放弃。管家执行结束或决定时只能在当前案卷内操作，并必须保存用户明确说出的原话。

1. 安装 DMG 或 ZIP 后，在设置中重新安装 Crewvane CLI。
2. 打开真实 Herdr 现场，普通拖动一段终端文本；看到 Herdr 的复制提示和 Crewvane 的“已复制 N 个字符”后，在 Crewvane 外部应用执行 `⌘V`，确认内容正确。
3. 将一条目标设置为已到期的跟进提醒，确认只出现“告诉管家”输入框和“1 小时后提醒”。输入“还在等”或“已经完成”并提交，确认消息离开注意力、目标状态在管家写回前保持不变，Herdr 管家实际收到原话。

1. 安装 DMG 或 ZIP 后，在设置中重新安装 Crewvane CLI，并按需安装或更新 Crewvane Skills。
2. 从“注意力”打开需要决定或验收的目标：使用轻量卡片完成操作；选择“完整记录”可查看消息、附件和目标管理。
3. 点击普通活动目标或真实会话介入事项，确认直接进入真实 Herdr 现场。顶部目标条可返回注意力或查看目标记录；隐藏终端不会关闭 Agent 会话。
4. 到期跟进和派发失败仍在卡片内处理；已结束目标只打开历史记录，不重新打开已经关闭的现场。
5. 确认目标说明、下一步和验收事实仍来自结构化 Crewvane 记录。现场原文用于操作与核对，不会自动注入 Agent 上下文或被当作验收依据。
6. 如需验证升级保护，可选择旧版状态目录。应用应显示“旧版工作区已自动保护”，原文件应完整存在于显示的 `.crewvane.backup-*` 目录中，新工作区可以正常创建目标。

## 0.5.2 安装与验收

0.5.2 只提供 Apple Silicon Mac（arm64）安装包，没有旧版工作区兼容层；首次使用请选择新目录。此版本仍未进行 Apple Developer ID 签名与公证，下载和首次打开时按上文的来源、SHA-256 与隐私安全提示处理。

1. 安装 DMG 或 ZIP 后，在设置中重新安装 Crewvane CLI。
2. 在“让外部 Agent 会使用 Crewvane”中安装或更新 Skills，并确认检测到的目标目录显示为已安装。已有同名且非 Crewvane 管理的 Skill 会被保留。
3. 打开真实 Herdr 现场，确认终端可拖动、调整大小、全屏、隐藏，并可用系统剪贴板复制粘贴。移动或关闭 Pane 后，Crewvane 应更新现场身份与可达状态。
4. 在终端里与 Agent 对话后，确认目标语义仍需 Agent 用 Crewvane CLI 显式写回；终端输出不会自动生成消息、进展或验收结果。
5. 配置企业微信 Webhook，将同一目标进入待验收，确认只收到一条 `attention.required` 消息，不再同时收到 `goal.status_changed`。
6. 从注意力打开决定、验收和到点跟进目标，确认当前依据、主操作与完整对话在同一弹窗内可见；1024×720、深色和浅色布局均无横向溢出。
7. 点击左上角“我的工作台”，确认当前工作台首页有明确选中态；在目标管理中选择“放弃目标”，确认会打开应用内原因输入并成功记录，而不是点击无反应。

## 本地制作与验收

在 macOS arm64 上执行：

```sh
pnpm install --frozen-lockfile
pnpm desktop:dist
pnpm test:installers
```

附件输出到 `apps/desktop/release/installers/`。验收会核对 SHA-256、磁盘映像、ZIP 解压、DMG 复制、完整代码签名和下载隔离属性，然后启动两种安装结果，确认新界面、renderer 隔离、图标元数据，并安装包内 CLI 实际创建目标。它不需要模型账号；Herdr 闭环另由桌面 E2E 与真实隔离 Session 试用覆盖。

## 维护者发布步骤

1. PR 的 **Desktop installers** 工作流执行类型检查、测试、打包与安装验收。
2. 合并前确认真实试用记录和所有未解决风险。
3. 根目录和桌面包版本一致后，创建并推送完全匹配的标签，例如 `v<version>`。
4. 标签工作流重跑验收，再创建包含 DMG、ZIP、SHA256SUMS 和说明的 prerelease 草稿。
5. 检查附件与说明后发布。发布后真实下载所有附件，核对 SHA-256，并在一台独立 Mac 上启动应用和安装 CLI。

标签工作流不合并 PR，也不自动公开 Release。
