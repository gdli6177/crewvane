# 现场答复与注意力同步验收

## 自动回归与 Skill 协议评估

| 场景 | 预期 | 自动验证 |
| --- | --- | --- |
| 当前负责人提交现场用户原话 | 持久化原话与摘要，注意力保留到管家核对 | core `scene-reply.test.ts` |
| 管家记录明确决定 | 原话写入决定账本，清除对应事项，原负责人不变 | core 与真实 CLI 回归 |
| 新问题或新答复已替换 | 旧 scope 拒绝写入，不能清新事项 | core 与真实 CLI 回归 |
| 重试相同回执 | 不重复消息与派发 | core 回归 |
| 只查看 / 生命周期变化 | 不当作用户已经决定或验收 | core 与 desktop reconciliation 回归 |
| 升级后的旧负责人 | 工作回合结束且确认空闲后补核对一次 | desktop reconciliation 与 Herdr runner 回归 |
| 正在工作、阻塞、未知或 Pane 已替换 | 不自动输入 | Herdr runner 回归 |
| 核对失败、离线、重启 | 保留事项、持久回执与重试入口 | reconciliation 回归 |
| 自定义 CLI 启动 | 同样获得现场回写协议 | owner-launch 回归 |
| Skill 修改但应用版本相同 | 受管 Skill 显示待更新并安装新协议 | skill-installer 回归 |

Skill 评估重点：收到系统核对不是用户回答；顺承词不能替代批准；未写回不假称同步成功；外部提交 Agent 不代人批准，负责人提交回执，管家核对明确原话后记录状态。协议评估用真实 CLI 的 scope 和原话校验约束配合真实模型试用，不仅检查文档是否包含命令。

## 打包应用真实试用

使用独立工作区、独立 `crewvane-trial-*` Herdr Session 与本机已安装的真实 Agent CLI：

1. 创建目标，让负责人提出一个明确决定，注意力出现。
2. 从注意力进入现场，只查看再返回，事项保持。
3. 在现场用自然语言回答，负责人保存原话，管家记录决定。
4. 不点击桌面批准按钮，验证原事项消失、决定账本保留原话、原现场继续复用。
5. 新问题仍出现；拒绝把旧回执用于新问题。
6. 核对同步中与失败提示在浅、深主题下可读。

真实模型试用命令：`pnpm test:scene-sync`（需已安装并可用的模型 CLI；不会访问真实用户工作区）。自动传输测试不能替代模型试用。实际结果由执行时保存的隔离证据记录确认。

## 2026-11-09 本地验收结果

在 macOS Apple Silicon 打包应用中，使用真实 OMP 管家与独立负责人，先后通过同目录目标及独立项目目录目标的完整试用。用户只在负责人现场发送自然语言选择，负责人保存原话，管家记录决定；未点击桌面批准按钮，对应注意力消失，负责人引用保持不变。项目目录与工作区分开时，负责人子进程使用明确导出的 `CREWVANE_WORKSPACE`，没有在项目目录创建另一份状态。

CLI、core 与 desktop 共 158 项自动回归通过；桌面 UI 回归覆盖回执原文显示和状态文件即时刷新，真实终端回归保持通过。另复现并修复首次管家初始化的短回合漏报：模型已经回复就绪而 Herdr 报 `agent_prompt_stalled` 时保留这次送达，不重复发送初始化。

以上为本地修复分支的验收，不表示已经发布新的 GitHub 安装包。暂存事项与人工待办仅有独立产品方案，尚未实现。
