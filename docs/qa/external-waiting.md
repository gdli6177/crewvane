# 外部等待语义验收

日期：2026-11-10。修正 v0.6.5 及之前混用用户待处理、内部协调和外部等待的问题。

## 产品规则

| 实际情况 | 生命周期与入口 |
| --- | --- |
| 需要用户选择、确认、提供信息或操作 | `active` + 对应注意力；有成果待验收时为 `review` |
| 管家、负责人或工人仍需协调处理 | `active`，由原有巡检核对停滞，不把空闲当作完成 |
| 等待具名外部联系人、机构或服务 | `waiting`，显示“等待外部”及 `waitingFor`；执行负责人保留 |
| 先记下、未授权开始 | `backlog`，在待办池 |
| 稍后提醒 | 只修改 `remindAt`，不改变上述生命周期 |

到期跟进可以出现在注意力，但不证明外部已返回。用户交回管家后恢复 `active`，清除旧等待与提醒，保留原下一步，并在系统记录中保存此前的等待对象与时间；管家核查后显式重新建立外部等待。用户决定、验收或介入不能用普通留言或 `wait` 隐藏。

## 旧数据

有效 v2 工作区读取时纠正不合法等待，不整体归档或丢失目标：

- 缺少等待对象、等待用户、占位负责人、管家或已登记 Agent：恢复 `active`。
- 仍有决定、验收或介入事项：保留原注意力；有真实交付的验收使用 `review`。
- 原来等待用户但没有注意力：补回稳定编号的介入事项；没有现场也能打开操作卡片。
- 真正外部等待及到期跟进保留；旧版被等待对象覆盖的负责人恢复为原现场 Agent 或待分配负责人。
- 历史记录保持原样；纠正结果在后续状态写入时一同保存。

## 回归入口

1. `pnpm test`：核心命令、历史数据、巡检、CLI 真实进程、桌面展示与派发重试。
2. `pnpm test:external-wait`：真实打包应用读取旧快照；注意力与外部等待分组；无现场事项操作卡；编辑等待对象校验与负责人隔离；提醒不改状态；交回管家与重启恢复。
3. `pnpm test:desktop`：既有注意力、通知、目标、深浅主题和视口回归。
4. `pnpm test:task-pool`：暂存、本人执行、提醒与接管。
5. `pnpm test:onboarding`：实际自定义 CLI 接收更新后的身份说明与消息，验证等待反馈交回后为活动状态。

打包试用使用隔离的临时工作区，不修改用户正在使用的 Crewvane 数据或 Herdr Session。自定义 CLI 试用证明真实传输，不等同于验证模型在所有自然语言场景下都能正确识别外部第三方；模型行为场景见 `skills/crewvane/references/waiting-eval.md`。
