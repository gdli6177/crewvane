# 0.6.7 执行报错报告复核

复核依据为 2026-11-04 至 2026-11-10 的 Crewvane 执行事件汇总。报告中的 grep
命中会被每条历史事件内嵌的完整状态快照放大，因此本次按独立错误行为而不是文本
命中数判断。

## 已确认并修复

| 问题 | 根因 | 0.6.7 处理 |
| --- | --- | --- |
| `events.jsonl` 增长到约 2.9 GB | 每条 workspace 事件都写入完整 state | 事件只保存状态摘要；超过 16 MB 后在写锁内压缩到最近约 4 MB、最多 2,000 条完整事件 |
| `agent_pane_busy` 连续失败 | 新 Pane 尚未成为可用 shell 就启动 Agent | 只对明确的 busy 错误复用同一个 Pane，指数退避重试，最长 15 秒 |
| `timeout` 显示为派发失败 | Herdr 已提交 prompt，但生命周期确认超时被当成拒绝 | 保存为 `unconfirmed`；提示“已提交，等待现场确认”，不产生失败注意力，不自动重发 |
| `coordinator-scope.json` 短暂缺失 | 准备管家前删除 scope，写入也不是原子替换 | 删除 prepare 阶段的 `rm`；scope 使用同目录临时文件与 rename 原子替换 |
| 巡检 10 分钟升级缺少可操作信息 | 注意力只写通用“无进展” | 升级项包含目标标题、卡点原因和最后一条非巡检活动 |
| 本地缓存和临时文件持续积累 | 只有结束后附件按 30 天自动清理，Chromium 缓存与原子临时文件没有统一维护入口 | 每日后台清理旧缓存、旧日志和遗留临时文件；设置页提供占用统计与手动清理，固定安全根目录并拒绝符号链接 |

## 已有保护，本次补充回归

- 管家复用时必须同时匹配同 Session 下的受管 Agent 名和真实前台进程；Pane 仍在但
  Agent 名消失时不再视为可用。
- `agent_not_found` 的自动恢复依赖重新检查 Agent 列表；针对该边界的测试继续保留。
- 等待用户和 Agent 之外第三方的语义、待办池、目标重启和 UI/UX 升级由 0.6.6
  门禁继续覆盖。

## 确认不属于 Crewvane 缺陷

- `Retry deadline exceeded` 是具体 Agent CLI 的模型重试预算耗尽，Crewvane 只能保存
  真实结果，不能替第三方模型客户端续跑。
- “未找到 codex CLI”是启动命令指向未安装程序；设置中的启动命令与 Herdr 安装流程
  已提供修复入口。
- 6 秒内连续六次 `agent_not_found` 没有自动巡检证据，属于外部 Agent 或人工快速
  重复操作。Crewvane 对同一目标的在途 handoff 会合并；用户主动再次重试仍应由当前
  错误项触发，不应被误认为后台自动重发。

## 验收

- 单元/集成：CLI、core、desktop 的类型检查和测试全部通过。
- 真实 Herdr：启动 Pane、message timeout、scope 连续派发和巡检上下文进入打包应用
  回归。
- 安装包：ZIP/DMG、SHA-256、quarantine、严格签名、启动、内置 CLI 和目标写入。
