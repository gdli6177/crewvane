# 待办池验收

## 自动与真实界面检查

- `packages/core/test/task-pool.test.ts`：暂存重启、巡检排除、禁止隐式启动、个人完成、提醒与确认、附件及项目保留、并发派发幂等、移出恢复。
- `cli/test/cli.test.ts`：`capture`、`capture --self`、`goal start` 的真实调用层；错误执行归属被拒，提醒与完成走同源状态。
- `scripts/task-pool-smoke.mjs`：隔离工作区运行真实打包应用，经输入框保存图片、补充背景、退出重启、开始人工执行、设置/取消提醒、无需 Agent 完成、到期展示、浏览不清提醒、延期、移出恢复、再交给管家。
- 同一脚本保存深色、浅色和 960px 窄窗口截图，并检查页面没有脚本错误或横向溢出。
- 管家派发与负责人现场答复仍由 `test:scene-sync` 的真实模型试用验证；待办池界面烟测使用无效的隔离测试运行时，不借用用户真实会话。

## Skill eval

| 输入 | 预期操作 | 不允许 |
| --- | --- | --- |
| 先记住，有空再研究这个方案 | `capture`，保留原文 | `ask`、创建负责人 |
| 提醒我明天 9 点亲自去银行（已知时区） | `capture --self --remind-at <明确 ISO>` | 用 `wait` 伪装外部阻塞 |
| 开始做刚才那条，交给管家 | `goal start ID --by concierge` | 重建一个目标、丢失图片 |
| 给这条暂存补充一点背景 | `goal message ID --text ...` | `progress`、静默切成 active |
| 这件事我已经办完 | 人在桌面标记完成或直接使用 CLI；外部提交 Agent 不替人验收 | 伪造检查或 Agent 交付 |
| 受管管家试图 capture / start 另一个目标 | 命令拒绝 | 绕过案卷、直接编辑状态 |

人工记录不会自动理解日期、安排“今天”或解读模糊时间。当前通过可选时间控件或明确 CLI 参数设置提醒。
