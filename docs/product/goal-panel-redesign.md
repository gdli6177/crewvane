# 目标详情重设计：内容、状态与操作解耦

日期：2026-11-04
状态：交互原型、生产实现、打包应用与真实模型验收均已完成。

## 1. 设计判断

Agent 的真实输出主要是自然语言、Markdown、终端摘录和附件，内容边界不稳定。要求它每次稳定填写“问题、事实、选项、建议、风险、证据”等字段，会把模型输出质量变成为 UI 契约，信息缺失时还会诱导系统猜测。

目标详情不应把 Agent 的文本拆成一张张业务卡片。它只处理三个彼此独立的层面：

1. **内容层**：原样展示管家最新消息、用户消息、Agent 回传内容和附件。UI 不根据正文推断问题类型、批准意图或下一步。
2. **状态层**：由 Crewvane 或管家通过明确命令维护一个很小的状态枚举。状态只表达“为什么这件事出现在注意力里”。
3. **操作层**：根据状态提供当前可执行的产品命令，不解析正文生成按钮。

这层抽象足以承载不确定的自然语言，也不会把权限判断交给文本识别。

## 2. 最小数据模型

### 2.1 可查询字段

目标详情只依赖少量可靠的机器字段：

| 字段 | 作用 | 来源 |
| --- | --- | --- |
| `goalId` | 稳定关联目标、消息、附件和操作 | Crewvane core |
| `title` | 列表和详情标题 | 新建目标或管家明确更新 |
| `status` | 决定当前操作区 | 明确状态事件，不从正文推断 |
| `updatedAt` | 顺序和刷新提示 | core 时间戳 |
| `messages[]` | 原始文本、作者、时间、附件引用 | 管家/Agent 写回 |
| `sceneRef` | 存在时随时回到目标自己的 Herdr 现场 | Herdr adapter |

`messages[].body` 是不透明内容。它可以是纯文本、Markdown、日志片段或空的附件引用；UI 不要求固定标题，也不从中抽取结构化决定。

### 2.2 状态枚举

第一版只需要以下状态：

| 状态 | 含义 | 默认操作 |
| --- | --- | --- |
| `等你回复` | 管家需要人的意见、信息或授权 | 自由文本回复管家，可附图/文件 |
| `等你验收` | 已有可验收成果 | “验收通过”“退回修改”；可另行追问 |
| `等待外部` | 等他人、服务或计划时间 | 默认无需处理；可主动补充进展 |
| `需要你排障` | Agent 无法在当前环境继续 | “打开工作现场”，可同时留话 |
| `管家处理中` | 管家或负责人正在推进 | 无主操作；可给管家留言 |
| `已交管家` | 人刚完成一次交接 | 回执；等待下一次状态更新 |
| `已验收` / `已完成` | 目标结束 | 只读；可补充说明 |

状态不是页面自己猜出来的。Agent 或 Herdr 插件写回一条明确状态更新；即使正文写着“可以全量”，UI 也不会据此自动批准任何高风险动作。

## 3. 操作契约

内容与操作分开后，产品操作可以被稳定定义：

- `reply(goalId, text, attachments[])`：把人的原话发给管家。该操作本身不改变目标状态。
- `accept(goalId)`：明确记录验收通过。
- `return(goalId, text)`：带修改意见退回；文本是自由输入，不要求模板。
- `openScene(goalId)`：打开目标已有的 Herdr 现场。正常推进、等待、验收和排障时都可使用；没有现场时不显示入口。
- 状态变化由管家/CLI 的显式 `status changed` 事件写回，不从回复内容判断“继续”“可以”或“灰度”等词义。

优先级永远由状态决定。文本来自 Agent 还是人，不改变这个规则；附件也不会改变权限。

## 4. 弹窗结构

目标详情是一个宽工作台式弹窗，桌面优先，不设计手机布局。从“注意力”和“全部目标”打开的是同一个组件。

### 4.1 顶部

- 目标上下文和最近更新时间。
- 目标标题。
- 当前状态。
- 目标已有负责人现场时，常驻“回到现场”；它属于导航能力，不随业务状态消失。
- 关闭按钮。

### 4.2 正文

- 首屏拆成三块事实：“现在发生了什么”由注意力和交付记录直接给出，“接下来怎么走”读取显式下一步，负责人、等待对象和提醒时间紧随其后。
- 最新一条 Agent 实质反馈优先作为“最近交接”原文显示；更新更晚但未带实质反馈的人工补充不会遮住它。自然段和换行原样保留。
- 附件作为独立资源列出，不要求 Agent 将内容摘要进结构化字段。
- 目标说明始终展示原文摘要，长文本限制为三行并可展开全文，避免被最新消息替换后失去原始上下文。
- 当前目标的“你 ↔ 管家”问答、管家与负责人的回传都属于同一条目标消息流；历史默认展开，最新记录在上，用户无需反复点开才能判断发生了什么。
- 历史以 `goalId` 隔离。从注意力或全部目标打开同一目标时看到同一份历史，不会把其他目标的内容混进来。
- 不渲染“事实 / 选项 / 建议 / 证据”等强制信息卡，也不进行正文语义解析。

### 4.3 底部操作区

底部只渲染一组与状态对应的操作：

- `等你回复`：自由文本框和附件按钮。
- `等你验收`：主操作“验收通过”，次操作“退回修改”；“有疑问，问管家”进入自由回复。
- `等待外部`：显示“现在不用处理”，另留低优先级入口提交新进展。
- `需要你排障`：主操作“打开工作现场”，次操作“告诉管家”。
- `管家处理中`：显示正在处理，不制造无意义按钮。
- `已结束`：只读，可补充说明。

回复框没有“选择方案”字段。用户写下什么就发送什么；系统不会把“看过了”解释为已处理，也不会让阅读动作自动移出注意力。

## 5. 为什么这比结构化交接更可靠

- **对 Agent 宽容**：不需要每次产出同样字段；缺少标题或证据时仍能完整显示。
- **不会制造假结构**：不会把建议误标为事实，也不会把两个自然段强行识别成互斥选项。
- **权限边界清楚**：审批、验收、退回由明确命令触发；自然语言回复不会越权。
- **状态可恢复**：界面可随时从 core 重放，不依赖上一轮消息格式。
- **更容易接不同 Agent**：Herdr 中的任意 CLI 只要能写消息和调用 CLI 状态命令即可参与。
- **以后可增强**：需要做富预览、引用卡片或特定业务表单时，作为附件/消息中的可选渲染插件加入，不改变核心状态机。

## 6. 示例

### 需要人回复

管家发来一段自然语言，说明回归结果、SSO 未验证和建议灰度。正文原样显示；底部是自由回复。用户输入“先灰度，明早看结果”只是消息，Crewvane 不自动把它记成部署批准；管家必须另行执行对应授权流程。

### 等待外部

管家说明正在等 YR 的沙箱密钥。底部明确显示“现在不用处理”。用户若先拿到进展，可以主动补充，不要求先修改状态。

### 等待验收

管家给出访谈结论，并把文档放在附件。底部只有“验收通过”“退回修改”两个明确状态命令；点击“退回修改”后才要求写下修改意见。普通提问不会通过或退回目标。

### 需要排障

系统钥匙串阻挡 Agent 继续工作。底部主操作为“打开工作现场”，避免要求人先在一个表单里描述无法继续的原因。

## 7. 原型边界与实现顺序

本轮先验证目标详情的信息组织与操作，随后已在生产桌面应用实现。生产代码不再使用单一巨型组件：展示状态、消息历史、附件、回复编辑器和状态操作各自解耦，并通过显式 `GoalDetailService` 接入应用。

原型入口：`http://127.0.0.1:4173/`

代码：`prototypes/goal-panel/`

验收截图：`/tmp/crewvane-goal-panel-decoupled-qa/`

生产实现：

1. 固定状态枚举和显式状态更新命令。
2. 让消息正文和附件成为独立、可追加、不可由 UI 改写的记录。
3. 将详情弹窗改为一列原始内容加状态驱动操作区。
4. 把“注意力”和“全部目标”统一到同一详情组件。
5. 接入 Herdr 现场的打开命令；已有现场时在目标弹窗顶部常驻入口，排障状态再把它提升为底部主操作。
6. 用真实管家、负责人和附件目标完成端到端试用后，再决定是否添加轻量富渲染。

目标消息与状态命令严格分离。`goal.message` 和 Herdr `direct` 只追加原话及附件，不按正文改变 `status`、`next` 或等待对象；等待提醒被回复时只清除已处理的到期注意力。管家读取用户明确语义后，通过结构化状态命令继续等待、恢复推进、验收、完成或放弃；结束和决定必须保存用户原话。

结构化摘要如果以后被证明有价值，应当作为 Agent 输出的可选消息渲染器，而不是 UI 运行所需的前提字段。

在 Herdr 中直接输入的终端内容，只有经过 Herdr 插件、Crewvane CLI 或会话回写器关联到当前 `goalId` 后才会出现在这里。设计不承诺从任意终端屏幕或日志中猜测归属；无法证明目标归属的消息不能混入目标问答历史。
