# Crewvane 模块化与插件化架构

日期：2026-11-04
状态：架构约束；首个目标详情模块按此拆分

## 1. 插件化不是把所有东西都搬出主程序

Crewvane 先保证一个可靠内核，再把会变化的部分放到稳定的能力边界后面。外部插件、随应用分发的第一方功能和内置实现使用同一套贡献协议。内置能力不能绕过协议直接写状态，否则一旦需要替换就会形成隐性耦合。

核心原则：

1. **内核窄而稳定**：目标、原始消息、附件、注意力、状态、命令和决定账本属于领域内核。
2. **能力声明，不继承实现**：插件声明自己提供什么能力，不依赖另一个插件的类或内部文件。
3. **状态单向流动**：插件提出命令或事件；内核校验、串行执行、持久化后发布新快照。
4. **原始内容与解释分离**：Agent 输出保持不透明字符串或附件，核心不解析自然语言来生成权限操作。
5. **内置与第三方同协议**：Herdr、终端、通知、存储、Agent 启动和 UI 贡献都通过适配器接口连接。
6. **失败可降级**：可选插件失效时，核心仍能记录和查看目标；必要能力失效时给出明确恢复路径。
7. **权限显式**：插件 manifest 声明读写状态、执行进程、网络、通知或 UI 扩展等能力，不按插件名称暗中信任。
8. **版本可协商**：协议带版本，加载前检查兼容性；未知字段可忽略，破坏性变化提升主版本。
9. **可观测和可撤销**：每次插件命令有来源、版本和请求 ID；有启用、停用、卸载和故障隔离状态。
10. **领域流程不进内核**：开发、设计、发布等工序由 Agent skill、任务文本或流程插件提供，不作为所有目标必经的数据结构。

## 2. 分层结构

```text
┌──────────────────────────────────────────────────────────────┐
│ 表现层：桌面功能模块、Herdr Pane、外部 Board、可选富视图      │
└───────────────────────────┬──────────────────────────────────┘
                            │ 查询视图 / 提交命令
┌───────────────────────────▼──────────────────────────────────┐
│ 应用层：命令总线、状态快照、查询、事件、来源与权限上下文       │
└──────────────┬───────────────────────────┬───────────────────┘
               │                           │
┌──────────────▼─────────────┐  ┌──────────▼───────────────────┐
│ 领域内核                    │  │ 适配器注册表                 │
│ Goal / Message / Attention │  │ execution / terminal / notify│

               │                           │

```

### 2.1 内核

内核只依赖标准类型和存储接口，不依赖 Electron、React、Herdr 或某个 Agent CLI。

稳定对象：

- `Goal`：标题、原始说明、当前状态、下一步、负责人引用、附件和活动记录。
- `Activity` / `GoalMessage`：按 `goalId` 隔离的原始消息与附件事实，不对正文做语义推断。
- `Attention`：说明为什么需要人，不保存某一种界面的按钮结构。
- `Decision`：人明确做出的批准或拒绝，以及原话、来源和时间。
- `CrewvaneCommand`：唯一写入口。桌面、CLI 和插件都提交命令。
- `WorkspaceEvent`：提交成功后的追加事件，供索引、通知和即时界面消费。

内核禁止：

- 读取某个 Agent 的终端画面来猜测目标归属。
- 根据文本中的“可以”“继续”等词自动生成批准。
- 直接执行 shell、访问 Herdr 或发送系统通知。
- 引用 React 组件、CLI 参数解析器或插件文件路径。

状态的所有权不随界面或插件转移：

| 入口 | 可提交 | 不允许 |
| --- | --- | --- |
| 桌面消息框、CLI `goal message`、Herdr `direct` | 原始文本、附件、待派发请求 | 根据正文改状态、下一步、授权或验收 |
| 管家 / 负责人协议 | 明确的 progress、wait、delivery、decision 事实 | 跳过目标作用域和核心校验直接写文件 |
| 人的明确操作 | accept、rework、resolve、resume 等 | 把“看过了”“可以”自动解释成操作 |
| Agent Runtime Adapter | 受限 attempt/turn 事件、Hook 安装状态与错误 | 把 Stop、工具调用或回复文本解释成完成、等待、决定或验收 |
| Herdr、通知、自动化插件 | 已声明能力范围内的命令和事件 | 直接修改 state、伪造完成或绕过决定账本 |

一次状态变更的顺序固定为：校验调用来源与目标 → 检查当前状态和业务前置条件 → 获取工作区锁 → 修改内存状态 → 原子持久化 → 追加事件 → 发布新快照 → 异步执行可选副作用。副作用失败不回滚已经成立的用户事实；例如通知失败保留目标并产生可重试错误，旧请求回执不能覆盖新状态。

### 2.2 应用服务

应用服务负责一次事务：校验命令、取得工作区锁、修改内存状态、原子持久化、追加事件，再返回新对象或快照。异步副作用在提交之后分派，失败不回滚已经成立的用户事实。

所有外部入口带来源上下文：

```ts
interface InvocationContext {
  source: "desktop" | "cli" | "herdr-plugin" | "automation" | "plugin";
  actorId?: string;
  pluginId?: string;
  pluginVersion?: string;
  requestId: string;
}
```

来源用于审计和权限判断，不能代替操作系统身份验证。

### 2.3 适配器

适配器是一个能力包，可同时包含后台逻辑和声明式 UI。建议的最小接口：

```ts
interface CrewvaneAdapter<TConfig = unknown> {
  manifest: AdapterManifest;
  activate(context: AdapterContext<TConfig>): Promise<Disposable>;
}

interface AdapterManifest {
  id: string;
  version: string;
  kernelApi: string;
  capabilities: Capability[];
  contributes?: {
    commands?: string[];
    queries?: string[];
    eventConsumers?: string[];
    views?: ViewContribution[];
  };
}
```

首轮稳定能力域：

| 能力域 | 作用 | 可选失败的结果 |
| --- | --- | --- |
| `storage` | 快照、事件和附件 | 必需；失败时工作区只读并提示恢复 |
| `execution` | 把已校验任务交给负责人或工人 | 目标保留，显示派发失败和重试 |
| `terminal` | 展示或聚焦真实终端现场 | 不影响目标事实，可改用外部 Herdr |
| `agent-discovery` | 发现本机 CLI 与启动能力 | 只影响新建会话，不影响已有目标 |
| `agent-runtime` | 通过官方 Hook / Extension 观测会话、turn、阻塞与 Agent 回复 | 回退到 Herdr 生命周期与 Watchdog；不能改变业务状态 |
| `notification` | 系统通知、Webhook、提醒、摘要 | 进入注意力但不丢目标；失败渠道独立退避 |
| `automation` | 定时跟进、巡检、外部触发 | 核心手动操作仍可用 |
| `view` | 目标详情增强、项目面板、业务预览 | 回退到标准原文视图 |
| `integration` | GitHub、飞书、日历等外部系统 | 状态保留，集成错误单独显示 |

### 2.4 UI 贡献

UI 不直接读取插件内部对象。插件只接收内核生成的只读视图模型：

```ts
interface GoalDetailContribution {
  id: string;
  placement: "goal.summary" | "goal.content" | "goal.actions" | "goal.history";
  when?: { status?: string[]; attentionKind?: string[] };
  renderer: SandboxedRenderer;
}
```

界面扩展遵守：

- 操作按钮产生标准命令，不直接修改 React 状态树。
- 内容渲染器只接收目标可见字段和当前用户可见的附件。
- 富预览崩溃只影响自己的区域，不能拖垮目标详情。
- 第三方富 UI 至少与网络、文件系统和进程能力分离；远程 UI 需要显式权限。
- 第一方目标详情是完整降级界面，任何扩展都不是查看目标的必要条件。

## 3. 目标详情当前采用的模块边界

目标详情位于 `apps/desktop/src/features/goals/`。模块拥有：

- 目标状态到展示文案的映射。
- 原始消息与折叠历史。
- 附件选择、拖放、粘贴和预览。
- 状态驱动的标准操作。
- 与 core 的命令接口，不直接写 state 文件。

目标详情不拥有：

- 跨目标路由和注意力排序。
- Agent 启动、Herdr 会话和运行时探测。
- 决定账本的持久化。
- 从自然语言回答中推断批准、验收或完成。

“工序”已从产品入口移除。未来如果需要可视化某类项目流程，它应作为可选流程插件或 Agent skill，而不是重新进入 `Goal` 的必填模型。

## 4. 插件生命周期

1. 发现 manifest，校验签名、来源、内核版本和能力范围。
2. 加载插件配置，执行向后兼容迁移。
3. `activate` 注册命令、查询消费者、事件消费者和 UI 贡献。
4. 运行期间命令和事件带插件身份，错误隔离并限流。
5. `deactivate` 注销贡献，等待在途请求结束，不删除持久事实。
6. 卸载只移除插件代码和配置；目标历史、决定和附件仍由核心拥有。

内置能力也经历同一生命周期，可用功能开关停用，以便验证降级路径。

## 5. 插件权限

权限按能力授予，例如：

```text
state.read.current-goal
state.command.goal.message
process.spawn.user-configured
terminal.herdr
network.github.com
notification.system
view.goal.actions
```

默认拒绝未声明能力。高风险命令仍经过内核治理，插件权限不会绕过人批准、验收或项目上线策略。

## 6. 演进顺序

### 第一阶段：先模块化

- 抽出目标详情、注意力列表、Agent 启动和 Herdr 连接的功能模块。
- 为命令、查询、事件和视图模型建立显式类型。
- 内置实现使用依赖注入，不在模块内直接引用 Electron 或 DOM。

### 第二阶段：稳定贡献协议

- 引入 manifest、能力注册表和生命周期。
- 将 Herdr 插件、通知、Agent 发现改为同协议适配器。
- 增加启用、停用、超时、重试和隔离日志。

### 第三阶段：开放扩展

- 提供本地插件 SDK 与示例。
- 支持可选视图、外部集成和自动化贡献。
- 再根据真实需求开放远程安装和签名分发，不让插件市场反向决定内核复杂度。

## 7. 验收标准

- 移除任意可选适配器后，目标仍可创建、查看、消息交流、等待和验收。
- 替换执行适配器不需要修改 core、CLI 命令或目标详情状态机。
- 新 UI 模块只能通过公开视图模型和命令接入，不导入别人的内部文件。
- 所有插件写入都能追溯 `pluginId`、版本和 `requestId`。
- 同一自然语言文本不能同时被两个插件解释成相互冲突的授权操作。
- 禁用流程插件后，既有目标仍保留原始消息和完成记录。
