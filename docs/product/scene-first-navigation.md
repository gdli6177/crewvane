# 场景优先导航与验收

状态：0.6.0 实现。

## 产品原则

目标是工作的事实来源，Herdr 是实际执行现场。用户不需要先在目标详情里读完所有历史，才能进入正在工作的会话。

| 入口 | 打开内容 | 理由 |
| --- | --- | --- |
| 真实 Agent 介入 | 直接打开已登记 Herdr 现场 | 登录、确认或终端排障只能在现场完成 |
| 需要人处理但没有现场 | 轻量操作卡 | 历史等待修正后仍能留言、联系管家或查看记录，不打开不存在的现场 |
| 需要决定 | 轻量决定卡 | 展示问题与最近负责人交接，输入原话后批准或拒绝 |
| 需要验收 | 轻量验收卡 | 展示交付、位置、真实检查与退回操作 |
| 到期跟进 | 轻量跟进卡 | 展示等待对象与下一步，直接继续、跟进或稍后提醒 |
| 普通活动目标 | 有真实引用时打开 Herdr 现场 | 无需经过中间详情页 |
| 派发失败 | 轻量重试卡 | 目标已保存，恢复管家联系后继续 |
| 等待外部或尚未建立现场且没有注意力 | 完整目标记录 | 可管理、查看附件或联系管家 |
| 已完成 / 已放弃 | 历史记录 | 现场已关闭，不制造可继续执行的错觉 |

完整记录仍是显式入口，不承载日常默认导航。现场条提供“回到注意力”和“目标记录”，显示项目、状态、目标标题与当前结构化事项。

## 数据边界

- 导航只读取目标生命周期、明确的 `attention`、提醒与真实 `HerdrReference`。
- 决定依据来自负责人通过 CLI 写入的交接或进展，不解析终端日志猜测结论。
- 验收只消费 `Delivery` 中的成果与真实检查；终端 `idle` / `done` 不代表完成。
- 现场条只读取短的结构化字段。终端历史是冷数据，保留在 xterm / Herdr，不注入 Agent 上下文。
- 动作卡复用同一组 core 命令，不建立另一套状态或自动推断批准。

## 验收

1. 真实介入与有现场的普通活动目标点击后打开 Herdr，没有先出现完整详情弹窗。
2. 决定卡可看到问题和负责人交接，批准后清除注意力并保留决定账本。
3. 验收卡可查看成果和检查、填写退回说明、再次验收；动作成功后回到注意力。
4. 到期跟进只保留“告诉管家”和一个自由输入框；人描述当前情况后，由管家决定继续等待、推进或结束。派发失败保留重试入口。
5. 已结束目标只打开记录；现场目标条随目标切换，返回注意力不终止会话。
6. 1408×880、1280×800、1024×700 与深浅主题下无横向溢出、遮挡、低对比度或过小操作目标。
