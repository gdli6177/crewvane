# 待办池与人工事项设计建议

状态：待评审的产品方案，尚未实现。与现场注意力同步修复分开交付。

## 目标

让“先记住、还不开始”和“需要我自己去做”的事情有明确去处，避免它们伪装成正在执行或等待 Agent 的目标。继续使用一个自然语言输入框，不要求填写下一步表单。

## 入口与信息结构

新增统一的“待办池”，包含“暂存”与“我来做”两个视图。同一个输入框旁提供三个清楚的提交动作：

| 操作 | 含义 | 是否启动负责人 |
| --- | --- | --- |
| 先记下 | 收集想法和未来工作，尚未授权开始 | 否 |
| 我来做 | 由本人执行，管家帮助记录安排与提醒 | 否 |
| 交给管家 | 现在交给管家协调执行 | 按需启动独立负责人 |

从项目视图记录时沿用项目上下文。项目与提醒时间均可选；可以自然语言补充，也可之后修改。暂存事项可一键“我来做”或“交给管家”；保留原文、图片与所有变更记录，不重复创建。

## 生命周期和执行归属分开

“暂存 / 已开始 / 等待 / 待验收 / 已结束”表达进展；“本人 / Agent”表达执行归属，两者不互相代替。

- 暂存不进入执行队列，不派发、不提醒、不跑停滞巡检。设定明确启用日期后，到期提醒是否开始，仍不自动启动 Agent。
- 我来做默认出现在人工待办中；安排到今天或明确提醒到期时进入注意力。未到期的人工事项不占据需要立即处理的列表。
- 人工事项的“完成”直接保存明确确认并结束，不强制制造 Agent 交付或验收过程。需要 Agent 帮助时，用户随时交给管家。
- 等待必须有真实阻塞对象或事件，不能把“尚未打算开始”记为等待。管家不擅自把暂存事项启动。
- 删除暂存事项保留可恢复记录；永久删除、附件保留期与目标删除统一制定，不在本方案中暗改现有规则。

## 验收依据

1. 用一句话保存暂存事项，重启后仍在，Herdr 不新增会话。
2. 暂存超过停滞阈值仍不进入注意力，不触发看门狗。
3. 人工待办设明天提醒，今天不打扰，到期准确出现。
4. 人工完成无需填写成果表单，也不启动 Agent。
5. 暂存转给管家只派发一次，原始内容、附件与历史连续保留。
6. 用户说“先别做”时记录为暂存；语义不明确只澄清是否现在开始。
