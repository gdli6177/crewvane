# 待办池与人工事项开发说明

状态：已确认，与现场注意力同步修复一起实现。本文为开发与验收依据。

## 目标

让“先记住、还不开始”和“需要我自己去做”的事情有明确去处，避免它们伪装成正在执行或等待 Agent 的目标。继续使用一个自然语言输入框，不要求填写下一步表单。

## 入口与信息结构

新增统一的“待办池”，包含“先记下”与“我来做”两个视图。同一个输入框上方选择安排，底部保留一个提交动作：

| 操作 | 含义 | 是否启动负责人 |
| --- | --- | --- |
| 先记下 | 收集想法和未来工作，尚未授权开始 | 否 |
| 我来做 | 由本人执行，管家帮助记录安排与提醒 | 否 |
| 交给管家 | 现在交给管家协调执行 | 按需启动独立负责人 |

从项目视图记录时沿用项目上下文。无需选择项目或填写提醒，正文和图片一起保存；提醒在详情中按需设置，不从自由文本猜测时间。暂存事项可一键“我来做”或“交给管家”；保留 ID、原文、项目、图片与所有变更记录，不重复创建。

## 生命周期和执行归属分开

“暂存 / 已开始 / 等待外部 / 待验收 / 已结束”表达进展；“本人 / Agent”表达执行归属，两者不互相代替。

- 暂存使用 `status=backlog, mode=manual`，不进入执行队列、不派发、不跑停滞巡检。默认不提醒；明确设置提醒后，到期只提醒是否开始，仍不自动启动 Agent。
- 我来做使用 `status=active, mode=manual`，出现在人工待办中；明确提醒到期时进入注意力。未到期的人工事项不占据需要立即处理的列表。提醒不把人工事项伪装成等待他人。
- 人工事项的“完成”直接保存明确确认并结束，不强制制造 Agent 交付或验收过程。需要 Agent 帮助时，用户随时交给管家。
- 等待必须有用户和所有 Agent 之外的具名外部第三方，不能把“尚未打算开始”、等用户或内部 Agent 协调记为等待。管家不擅自把暂存事项启动。
- “移出待办池”使用 `goal.drop` 保留记录；可在全部目标 → 已放弃中恢复。没有执行现场的个人事项通过 `goal.restore` 回到暂存，不自动派发。永久删除继续只允许已结束事项，附件沿用结束后 30 天清理规则。
- 仅查看事项、补充说明都不清除人工到期提醒。“知道了”只确认本次提醒；“1 小时后提醒”延期；开始、完成、移出是独立明确动作。

## 协议与模块

- `goal.intake.handling`：`concierge`（默认）、`later`、`self`；core 保留原文，不按关键词切换安排。
- `goal.takeover`：暂存 → 人工执行。`goal.delegate`：暂存或人工执行 → 管家执行；重复请求返回同一派发编号。
- 暂存的 `progress`、`wait`、`review`、`decide`、状态更新、派发和现场登记被拒；编辑说明、追加备注、设置提醒、明确完成或移出仍可用。
- `capture TEXT [--self] [--remind-at ISO]` 用于外部 CLI/Skill 记录。`goal start ID --by self|concierge` 明确开始；受管管家不能借此启动其他案卷或暂存工作。
- 管家已直接收到新的终端事项时，通过 `direct --new --handling later|self` 写回对应待办；不建立派发。已有事项的 `direct` 仍只追加备注，不能用 `--handling` 变相改变执行安排。
- 核心规则在 `packages/core/src/task-pool.ts`，页面与简约详情在 `features/tasks/`，统一输入在 `features/intake/`。桌面、Herdr 控制台与 CLI 共用同一快照。
- UI 在最近提醒到期时刷新一次，无需后台轮询终端或扩大 Agent 上下文。

## 验收依据

1. 用一句话保存暂存事项，重启后仍在，Herdr 不新增会话。
2. 暂存超过停滞阈值仍不进入注意力，不触发看门狗。
3. 人工待办设明天提醒，今天不打扰，到期准确出现。
4. 人工完成无需填写成果表单，也不启动 Agent。
5. 暂存转给管家只派发一次，原始内容、附件与历史连续保留。
6. 暂存补充说明不会自动派发；外部 Agent 使用 Skill 时将明确“先记下”的意图映射为 `capture`，不使用 `ask`。
7. 仅查看和补充说明后提醒仍在；确认、延期和取消提醒后按明确操作收口。
8. 移出可恢复；恢复后保持暂存，既有原文、附件和历史保留。
9. 在打包应用中检查深色、浅色、窄窗口和重启恢复，不能只验证函数返回值。

验收入口：`pnpm test`、`pnpm test:task-pool`、`pnpm test:desktop`。
