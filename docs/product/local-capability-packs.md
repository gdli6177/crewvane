# 工作方法与本地能力包

## 目的

工作方法把一个团队或个人已经验证过的流程，转成 Agent 在目标执行时可以看到的
说明。它解决的是“同一类工作每次都要重新讲一遍”的问题，不负责调度、保存目标状态
或替代 Agent。

Crewvane 有三类 Skill：

| 类型 | 来源 | 作用 | 是否可被目标挂载 |
| --- | --- | --- | --- |
| 角色 | 内置 | 约束管家、负责人或独立复核者的职责边界 | 否，自动解析 |
| 工序 | 内置 | 标准交付、探索研究或发布检查的默认步骤 | 否，按目标类型自动解析 |
| 本地方法 | 用户安装 | 保存特定团队或个人的流程、清单与可选脚本 | 是，每个目标最多 8 个 |

内置名称使用保留前缀 `crewvane.`。第三方本地能力包必须使用独立命名空间，例如
`acme.release-review`。

## 用户流程

设置页的“工作方法”提供两个入口：

1. **让 Agent 创建**：复制一段说明给已安装 Crewvane Skills 的 Agent。Agent 通过
   自然语言补齐触发场景、步骤、验收证据和适用角色，使用
   `crewvane skill draft / validate` 生成并检查草稿，再在用户明确确认后安装。
2. **从文件夹安装**：用户通过目录选择器选择一个本地能力包。应用先验证并展示名称、
   版本、角色、说明、参考文件、文件数量和脚本摘要，再允许安装。

安装只表示方法进入工作区库，不表示任何目标会自动使用。目标详情中的“工作方法”
由用户或当前案卷管家显式挂载；移除时立即停止新的负责人或复核者解析该绑定。

## 目录与清单

最小能力包：

```text
acme.release-review/
├── manifest.json
├── SKILL.md
├── references/
│   └── checklist.md
└── scripts/
    └── inspect.sh
```

`manifest.json` 使用 `schemaVersion: 1`，包含：

- `id`、`name`、`description`、`version`；
- `minimumCrewvane`；
- `kind: "process"`；
- `roles: ["owner"]`、`["verifier"]` 或两者；
- `entry`；
- 可选 `references` 与 `scripts`。

脚本声明必须包含稳定 `id`、位于 `scripts/` 的相对路径、SHA-256 和用户可读用途。
完整示例见随应用安装的 `crewvane-local-pack-author/references/manifest.md`。

## 解析顺序

负责人或复核者启动前，按固定顺序组合上下文：

1. Crewvane Core 不可覆盖的边界；
2. 当前角色 Skill；
3. 当前目标类型的工序 Skill；
4. 目标挂载的本地方法，按稳定 ID 排序；
5. 本次目标或复核任务。

管家通知包含控制面角色、Agent 接入和现场恢复 Skills，以及当前工作区本地方法的
名称、状态和用途目录。管家只在目标确实匹配时通过 `crewvane skill attach` 挂载；
不会把每个本地方法的全文注入所有案卷。

## 上下文与性能边界

- 入口说明最多 12,000 个 Unicode 字符；
- 单份参考最多 12,000 个字符；
- 单个能力包的全部参考合计最多 24,000 个字符；
- 一个目标最多 8 个本地方法；
- 能力包最多 100 个文件、5 MB；
- 引用只接受 UTF-8 文本并拒绝 NUL 字节；
- 所有文件拒绝符号链接、绝对路径和目录穿越。

本地方法的内容会按目标绑定变化，因此每次负责人启动都重新校验内容摘要。目标记录
保存解析摘要与所用包版本，便于判断某次执行实际使用了什么内容。

## 脚本与信任

说明型方法是默认选择。只有确定性执行明显优于自然语言步骤时才使用脚本。

- 安装可以不带任何脚本授权；这样的包仍可提供流程说明；
- 用户必须逐项批准脚本，批准值绑定当前脚本 SHA-256；
- 包升级、脚本变化或整个包摘要变化会使旧授权失效；
- `crewvane skill run` 只允许运行当前目标已挂载、已授权且摘要匹配的脚本；
- 受管 Agent 只能为其当前目标运行脚本；
- 脚本环境只暴露必要的本地变量，不继承任意宿主变量；
- stdout / stderr 会截断，执行 120 秒后终止；
- 审计事件记录退出码和有界输出，但不改变目标生命周期。

脚本不是安全沙箱。它仍以当前用户权限运行，安装者必须确认目录来源和脚本用途。

## 状态边界

Skill、Hook 与脚本只回答“Agent 被告知该怎么做”或“执行过程发生了什么”。目标
完成、外部等待、需要人决定、交付复核和验收仍只能由 Crewvane 语义 CLI 写入。

特别是：

- Agent Stop 不等同于完成；
- 脚本退出码 0 不等同于交付通过；
- 方法说明中的“完成后自动验收”不能覆盖目标授权；
- 本地方法不能修改 Core 约束、管家唯一性、人工验收或高风险动作规则；
- 本地方法不能把自身的工具输出或终端全文写入目标。

## 启停与故障恢复

停用的能力包不能再挂载；已经绑定的目标会在下次启动负责人或复核者时失败关闭，
并提示启用或移除。删除本地包后，目标保留原绑定作为审计事实，界面显示“需重新
挂载”，不会静默按旧版本执行。

包缺失、摘要变化、解析失败或启动恢复无法确认时：

1. 不开始新的 Agent 回合；
2. 保存可操作的失败原因；
3. 需要现成负责人时使用 `crewvane owner attach` 校验真实现场；
4. 已可能送达的业务任务绝不自动重放；
5. 确认现场、重新安装或移除绑定后再由用户或管家决定下一步。

## 与 Herdr 解耦

0.10.0 把 Capability / Skill 与 Session 执行分开：

- Core、Skill 解析、CLI 语义写回和 Agent Hooks 不依赖 Herdr 内部命令；
- Herdr 仍是当前唯一完整落地的 Session Adapter，负责工作区、Tab、Pane、Agent
  启动与现场恢复；
- `owner launch` 的恢复以通用现场引用和 CLI 绑定命令表达；
- 未来实现 Native PTY 或其他外部终端 Adapter 时，业务流程无需重写。

因此 0.10.0 完成的是 Adapter 边界解耦，不是“可卸载 Herdr”。无 Herdr 运行需要
第二个覆盖创建、发送、观察、恢复、关闭和人工介入同步的完整 Session Adapter。

## 验收

自动回归覆盖清单校验、保留前缀、路径穿越、符号链接、二进制与超长引用、脚本摘要、
授权失效、停用、删除、目标绑定、解析去重、恢复 ID、Session 漂移和任务不重放。
打包应用回归还必须覆盖：

- 空态、预览与安装；
- 说明型与脚本型方法；
- 目标挂载与缺失提示；
- 浅色和深色主题；
- 真实 Codex 收到入口与参考内容；
- `owner attach` 恢复后没有重复业务任务；
- 三个并行目标的响应性检查。
