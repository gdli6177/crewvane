# Crewvane 0.6 开发与验收说明

状态：开发基线。本说明替代旧版运行时调度方案，作为实现、评审和验收的共同依据。

## 1. 要解决的问题

一个人同时处理多个项目、需求和个人事项时，需要在许多 Agent 会话之间反复切换。等待他人审批或等待 Agent 执行的事情尤其容易被忘记。

Crewvane 0.6 是一个**全局管家与注意力中心**。用户把事项告诉管家或记录为目标，Crewvane 统一保留下一步、等待对象、提醒和交付记录。只有真正需要人的事情进入注意力面板。

本版解决注意力和交付闭环，不再解决 Agent 运行时管理、自动调度或复杂权限编排。

### 已确认的产品决定

- 整个工作区只有一位全局管家，统筹多个项目和个人事项；不是一项目一管家，也不是一目标一管家。
- 管家是 Herdr 中一个持久 Agent 身份，不是 Crewvane 内另做的聊天窗。
- Herdr 负责终端、会话、Agent 启动和 Agent 间消息传递；用户可在 Herdr 中使用本机已有的 Codex、OMP、Cursor 等 CLI。
- 管家与目标现场在应用内显示 Herdr 终端，不要求打开外部 Terminal。同一工作区复用连接，收起面板后继续执行；恢复现场与重启应用不能创建重复管家或额外系统终端窗口。
- 用户只与管家沟通。管家只做目标分发、协调跟进与向人交接，不亲自执行目标；简单任务也交给独立负责人。目标记录、提醒和下一步维护属于协调工作，不要求为每次状态更新创建负责人；内部协调不向用户索要反复确认。
- 用户用自然语言交代事项与变化；目标、下一步、等待对象和跟进提醒由管家 / 负责人通过 CLI 维护。桌面的手动编辑表单仅是纠正与接管入口，不是每次推进的必经步骤。普通目标详情默认只读，人工决定和验收时才突出输入与操作。
- 注意力面板聚合需要决定、需要验收、到点需要跟进和 Agent 需要介入的事项。正常执行不打扰。
- 产品不再提供“工序”或必填步骤。人的原话作为不可变消息保存，开发、设计、测试等领域流程由任务原文、项目规则或对应 Agent skill 提供。
- 新目标支持文字与图片一起交代。图片通过粘贴、拖拽或文件选择进入，由可信主进程按魔数校验后保存；状态只记录元数据和 SHA-256，不保存 Base64。已结束目标的图片保留 30 天后自动清理，也支持逐张删除或永久删除整个目标。
- 验收以实际成果、检查记录和可访问的 Herdr 现场为依据。Agent 自称完成、Herdr `done` 或终端空闲均不等于验收通过。
- 项目可选择 `external-approval`、`auto-merge-manual-deploy` 或 `auto`；默认外部审批。Crewvane 只判定项目策略是否放行，不会替 Agent 执行 Git、部署或外发。
- 删除数据、停服、花钱、外部发消息、改变产品方向、新建或轮换密钥、修改权限、修改上线策略，九类动作在任何策略下都必须先问人。
- 旧版未投入实际使用。0.6 不读取 v1 语义，也不把它猜测转换成新目标；发现不兼容、损坏或缺快照的旧工作区时，先整库归档到相邻 `.crewvane.backup-*`，再自动创建可用的 v2 工作区，并在界面显示备份原因与打开入口。
- 注意力中的真实现场介入直接进入 Herdr；决定、验收、到期跟进和派发失败使用轻量动作卡。普通活动目标有已登记现场时优先打开现场；已结束目标保留历史记录。现场上方仅展示结构化目标事实，不把终端滚动内容注入 Agent 上下文。

## 2. 产品结构

```text
Crewvane 工作区
├── 注意力
│   ├── 需要你处理：决定 / 验收 / 到期跟进 / 会话介入
│   ├── 在等待：等待对象、下一步、跟进时间
│   └── 跟进中：精简进度摘要，不发送普通进度通知
├── 全部目标
│   ├── 项目筛选、状态筛选与搜索
│   ├── 场景优先：活动目标与真实介入直达 Herdr
│   ├── 动作卡：决定 / 验收 / 到期跟进 / 派发重试
│   └── 历史记录：原文、消息历史、附件、成果、证据与目标管理
└── 设置
    ├── 工作区与项目目录
    ├── Herdr 检测、安装和打开
    ├── Crewvane Herdr 插件自动部署与状态
    ├── 全局管家准备、恢复与故障反馈
    ├── Agent 偏好：管家 / 负责人 / 工人的启动命令，可跟随上一级
    ├── 项目上线策略：外部审批 / 自动合并后手发布 / 自动上线
    ├── 决定账本与高风险动作入口
    ├── 内置 Crewvane CLI 安装与 PATH 说明
    └── 系统通知、Webhook、浅色 / 深色外观

持久 Herdr Session：crewvane
└── 唯一管家 Tab：concierge
    ├── 目标 Tab（需要现场时创建）
    └── 独立负责人 / 执行 Agent（实际执行必须分发，已有现场则复用）
```

## 3. 范围与非目标

### 本版交付

1. macOS Apple Silicon 桌面应用，浅色 / 深色主题，可收起侧边栏。品牌为生图生成的像素魔法师，以深靛蓝、长春花蓝与薄荷绿构成克制的像素游戏气质；不使用管理后台式密集表格，正文和操作仍保持现代可读性。
2. 本地工作区及项目目录管理；项目没有 Git 仓库也可作为个人事项容器。
3. 目标创建、记录、更新、等待、提醒、请求决定、提交验收、通过、退回、放弃与完成。
4. 目标图片附件：粘贴、拖拽、文件选择、缩略图、原图打开、逐张删除、CLI 导入、Herdr 绝对路径传递与 30 天自动清理。
5. 一个持久 Herdr Session、一个全局管家、目标现场关联和打开现场。
6. 管家身份说明书：读取目标原文、项目规则和消息，通过 Herdr 联系负责人、写回实际结果。
7. 与桌面共用目标库的 CLI；面向人的消息入口与 Agent 状态协议使用明确命令边界，安装后不依赖源码目录、pnpm 或用户另装 Node。
8. 目标状态变化、到期跟进与需要介入的系统通知；可配置 HTTPS Webhook 按状态订阅去重后的事件，飞书 / Lark 与企业微信机器人开箱兼容，失败独立退避；应用重启后保持目标和提醒。
9. 随应用打包并自动注册的 Herdr 注意力插件：在 Herdr 内打开注意力控制台、单框新建目标、回到全局管家、补充决定、聚焦负责人现场，并通过 Herdr 原生 Agent 状态和 Pane 生命周期事件即时同步现场。
10. 模块化目标详情与适配器边界，为后续存储、执行、终端、通知、自动化和富视图插件保留稳定接口。
11. 场景优先导航、轻量动作卡与现场目标条；明确入口保留完整目标记录。
12. 完整测试、真实 Herdr 试用、DMG / ZIP 安装验收和签名验证。

### 明确不做

- 不扫描运行时，不配置模型，不接 ACP 或 Codex App Server。
- 不另做独立管家聊天协议；应用内终端仅使用 xterm.js 和 node-pty 呈现 Herdr TUI，不接管 Herdr 的会话或 Agent 通信职责。
- Herdr 插件只做终端表现和快捷动作，不保存第二份目标状态，不承担权限边界或操作系统沙箱。
- 不做旧版授权、合同、泳道、知识库、密码本、自动分支 / worktree 或调度器。
- 不自动解析全部终端日志来推断目标状态。
- 不做多用户、云同步、移动端、Windows / Linux 安装包。
- OpenViking 不进入本版依赖。若未来加入，只能是可选上下文适配器。

## 4. 领域模型与注意力规则

### 工作区

一个工作区保存一份 `.crewvane/state.json`、完整快照事件日志和写锁。`WorkspaceState.version` 为 `2`；发现其他版本、损坏 JSON、缺字段快照或只有旧事件日志时，先构造完整的新 v2 目录，再原子归档旧 `.crewvane` 并切换。旧执行状态、审批和 Herdr 现场不自动转换，备份供用户查看；有效 v2 不触发恢复。细节见 [工作区兼容检查与自动恢复](workspace-recovery.md)。

核心记录：

- `Project`：`id`、`name`、可选 `path`、`policy`。项目用于归类与提供目录上下文；项目策略只决定上线审批，不承担 Agent 运行时职责。
- `ProjectPolicy`：`shipPolicy`、`approvers[]`、修订号与更新时间。默认 `external-approval`，设置只能由人通过桌面执行。
- `DecisionRecord`：项目、稳定动作键、批准/拒绝、人的原话、来源、目标与时间；派生为 `.crewvane/decisions.md` 和 `.crewvane/rejected.md`。
- `Goal`：标题、原始说明、归属项目、模式（`concierge` / `manual`）、生命周期、等待信息、提醒、注意力原因、下一步、当前负责人、图片附件元数据、交付记录、Herdr 引用及时间戳。
- `Activity`：按 `goalId` 隔离的目标消息与处理事实，记录人 / 管家 / 负责人 / 系统的明确动作；`message` 保持原文和附件引用，Agent 答复不需要变成固定字段。
- `HerdrReference`：真实的 Session、Workspace、Tab、Pane 和 Agent ID。引用只用于定位现场，不表示任务结果。
- `Delivery`：成果摘要、交付位置、检查记录和可选 URL。检查记录包含名称、实际命令或操作、结果和说明。

状态中的 `workflows` 与 `steps` 只作为旧快照结构占位读取，不再出现在产品入口、CLI、目标详情或管家提示词中。

生命周期使用 `backlog | active | waiting | review | completed | dropped`。`backlog` 表示仅暂存、尚未授权执行；`active` 表示正在推进或管家可以下一步处理；`waiting` 表示等待真实外部结果；`review` 表示已提交给人验收。是否进入注意力队列由独立注意力或明确到期提醒决定，不能从 Herdr 空闲状态推断。

待办池是同一份 `Goal` 的投影：“先记下”为 `backlog/manual`，“我来做”为 `active/manual`。统一输入框通过 `goal.intake.handling` 选择 `later | self | concierge`。前两者不启动 Agent，也不参与停滞巡检；提醒是独立可选字段，不要求把人工事项改为等待别人。查看和追加备注不清除个人提醒。准备好后通过 `takeover` 或 `delegate` 复用原记录开始；人工完成不要求提交 Agent 验收材料。详见 [待办池开发说明](task-pool-proposal.md)。

`attention` 为 `null` 或：

```ts
{ kind: "decision" | "review" | "follow_up" | "intervention";
  summary: string;
  since: string;
  notifiedAt?: string }
```

### 注意力生成规则

| 条件 | 是否展示 | 是否系统通知 |
| --- | --- | --- |
| 管家 / 负责人明确请求人决定；上线策略要求审批 | 是，`decision` | 是，决定账本命中时除外 |
| 删除数据、停服、花钱、外部发消息、改产品方向、新建或轮换密钥、改权限、改上线策略 | 是，`decision` | 是，任何 ship policy 都相同；决定账本命中时直接沿用 |
| 提交了真实交付记录 | 是，`review` | 是 |
| 等待、暂存或个人执行的 `remindAt <= now` | 是，`follow_up` | 每个提醒时间最多一次，不自动启动 Agent |
| Herdr 对应 Agent 为 `blocked` / 不可达 | 先由巡检联系管家 | 管家不可达或联系后 10 分钟无恢复进展时通知 |
| 活跃目标的负责人 `idle` / `done` 持续 90 秒且没有写回结果 | 先由巡检联系管家核对现场、结果和下一步，显示“待管家核对” | 不直接通知；联系失败或 10 分钟无恢复进展时通知 |
| 活跃目标 30 分钟未写回实质进展 | 先由巡检联系管家，不以终端忙闲判定失败 | 管家不可达或联系后 10 分钟无恢复进展时通知 |
| Herdr 为 `working` / `idle` / `done` / `unknown` | 否 | 否 |
| 普通进展更新 | 否 | 否 |
| 等待他人但未到提醒时间 | 仅在“在等待” | 否 |
| 已完成 / 已放弃 | 否 | 否 |

人工在桌面更新的目标说明、下一步和提醒优先于自动同步。现场同步只更新独立的 `live` 状态。巡检先联系管家处理负责人问题；联系失败或 10 分钟没有恢复进展才产生自己的介入项，不覆盖人工决定或验收。`active` 是业务目标仍需跟进，不表示终端一直在工作；列表分别显示“执行中”“待管家核对”和“待管家跟进”，不把“回到现场”作为执行中状态。已明确等待他人、待验收、已结束和仅手动记录的目标不进行无进展催办。巡检记录不得被当作任务取得新进展，迟到的巡检结果不能覆盖任务的新进展。负责人恢复 `working` 或提交新的决定、交付时，旧的空闲核对提示立即失效。

## 5. Herdr 与管家契约

桌面通过固定可执行文件和 argv 调用 Herdr，不经 shell 拼接命令。Session 按工作区路径派生为 `crewvane-<路径摘要>`，可由显式环境配置固定。安装包在构建时下载并校验官方当前平台 Herdr，首次启动不依赖 Homebrew、网络或系统 PATH。应用启动后检测应用内置、私有 runtime、登录 shell PATH 与常见目录中的版本，并通过轻量 GitHub Releases API 检查更新；发现较新版本时下载官方当前平台二进制，再次校验 SHA-256 和可执行版本后安装到应用自己的 runtime 目录，不修改用户已有安装。更新检查或下载失败时继续使用应用内置或已有可用版本，并持续显示具体原因及重试入口；无可用 CLI 时记录、筛选、提醒和人工验收仍可使用。设置页显示实际路径、版本和检查更新入口。

Crewvane 插件随 `.app` 打包，Herdr 就绪且 CLI 可用后自动部署到 `userData/herdr-plugin` 并注册为 `dev.crewvane`。升级时按全部打包源码摘要原子替换，固定插件 ID 重新登记，不依赖 GitHub 再下载。插件提供“打开 Crewvane 注意力”“给 Crewvane 新建目标”和“回到 Crewvane 管家”三个动作：注意力 Pane 运行 `crewvane board`，新建 Pane 使用稳定的一行输入并调用 `crewvane ask`，回到管家动作按真实 Agent 身份聚焦 `concierge`。三者使用与桌面相同的 core 状态；注意力 Pane 可显示项目上线策略、审查轮次、高风险动作、决定、验收、跟进和介入，补充意见、提交批准或拒绝、请求跟进、等待事项交给管家或人工接管、验收通过、退回修改、聚焦真实负责人现场或按 `g` 回到管家；不自行执行目标。

插件清单同时订阅 `pane.agent_status_changed`、`pane.exited`、`pane.closed`、`pane.moved`、`tab.closed` 和 `workspace.closed`。事件脚本读取 Herdr 原生的 `{ event, data }` 环境变量并调用内部 `crewvane event herdr`；CLI 校验 Pane、Tab 或 Workspace 身份后只写回已经登记该现场的目标，陌生现场不产生写入。`pane.moved` 使用新返回的 Pane、Tab、Workspace 与 Agent 身份原子替换旧引用，后续状态和关闭事件只命中新 ID。桌面每 10 秒的 `agent list` 轮询仍保留，覆盖 Herdr 服务暂停、事件钩子故障和旧版插件。

Herdr 插件不是可靠性的捷径或安全边界。插件 v1 是无 SDK、无沙箱的普通 argv 进程，继承用户环境并可调用完整 Herdr CLI；原生非终端 UI 也不受支持。因此插件只作为可选表现层，Crewvane 的案卷限制、状态锁和权限校验仍由 CLI、core 和受约束 Electron IPC 承担。Herdr 不可用或插件安装失败不阻止桌面记录目标；设置页显示独立状态，修复后自动重试。

管家身份初始化与案卷处理始终是两个回合。初始化只记住职责并回复 `CREWVANE_CONCIERGE_READY`，不读取目标；案卷通知一次只带一个 `case_id`，同一工作区由上一条消息的 settled 状态串行解锁。每个案卷回合在分发、写回或交接后立即结束，禁止启动后台任务、循环轮询或等待负责人完工，避免下一条目标继承上一条的 scope。恢复已有管家时，只有 Herdr 的 `idle` / `done` 状态允许发送身份初始化；`working` / `blocked` / `unknown` 必须保留现有现场，“找管家”直接聚焦真实 Pane 让用户处理阻塞 UI，不能把 blocked 当成不存在，也不能自动发送 Enter、Esc 改变用户输入。已知 blocked 时后续派发返回清楚的可操作错误。案卷快照附带图片的真实绝对路径，并明确要求负责人实际查看；没有读取证据时不得声称看过。

Herdr 0.9.5 的插件 v1 事件没有用户 prompt 提交事件。直接终端聊天必须先由管家执行 `crewvane direct --current "<原话>"` 或 `crewvane direct --new "<原话>"` 写回共享状态，再继续处理；桌面监听状态文件并即时刷新。CLI 对已存在的当前案卷只追加用户消息，不建立重复 handoff；对终端中新建立的目标记录为已经送达管家，避免桌面回放同一原文，并原子推进管家的案卷 scope，使同一回合可以继续处理新目标。终端能提供可保存的本地图片文件时，管家为 direct 命令追加 `--attachment <路径>`，CLI 负责复制和校验；无法取得文件时明确要求用户回到桌面输入框附加，不能静默丢图。协议无法捕获不经过 CLI 写回的普通终端对话，UI 与文档必须明确这个边界。

应用打开工作区时读取状态，不控制用户其他 Session。准备管家时：

1. 检查 Herdr 和内置 CLI 是否可用。
2. 在命名 Session 内建立或找到 Crewvane 自己的 Herdr Workspace。
3. 查找已登记的管家 Tab / Pane / Agent；引用失效时核对真实列表，再决定恢复或重新创建。
4. 唯一的 `concierge` Tab 中使用用户填写的启动命令启动管家，默认 `codex`。命令解析为可执行文件与原生参数，可包含模型参数；已识别 CLI 交给 Herdr Agent 通道，自定义 CLI 将每个参数正确转义后在 Pane 内执行。不把设置原文当作 shell 表达式执行，不支持管道、重定向或变量展开。这只是管家启动方式，不重建运行时管理页面。
5. 将身份说明、工作区绝对路径、CLI 使用方式和当前目标摘要交给管家。

设置中的 Agent 偏好分别指定管家、负责人、工人的启动命令，例如 `codex --model <模型名>`、`npx --yes my-agent` 或自定义启动脚本。允许任意交互式 CLI，以及绝对路径、`~/` 和相对于工作区的脚本路径。Herdr 已识别的 CLI 使用原生 Agent 通信；未识别的命令通过 Pane 直接启动，保留原生参数，用真实前台 PID 复用和核验现场。发消息前检查原进程仍在前台，退出或被替换后禁止把任务发给 shell。未报告生命周期时为 unknown，不伪造工作或完成。普通终端模式下长身份说明按 Unicode 字符安全换行，防止超过 macOS 单行输入上限。负责人未设置时跟随管家，工人未设置时跟随负责人。分工前管家通过 `crewvane status --json` 读取最新偏好，当前目标里用户明确指定的命令优先。未指定模型时沿用 CLI 本机配置；不静默更换备用 CLI。复杂 shell 表达式与环境配置由用户自己的启动脚本承载。修改偏好不替换已经运行的会话，也不阻止恢复现有管家。安装检测不读取凭据或登录状态。

左上角工作台入口必须显示当前目录并解释工作区与项目的区别。选择目录后回到注意力页，显示切换成功；选择同一目录明确提示，取消保持原状，读取失败保留旧工作区和可见错误。“设置 → 打开 Herdr”不依赖成功准备管家，允许直接进入现场排错。菜单栏与 Dock 使用同一份像素魔法师应用图标。

桌面新建目标只有一个多行自然语言输入框，支持 `⌘ / Ctrl + Enter` 提交，不要求填写项目、流程、等待对象或提醒表单。完整原文保存为 `description` 和首条动态，首行仅作为初始标题。目标通知同时携带当前原文、附件和最近动态的快照，不能要求不支持工具调用的自定义 CLI 必须先执行 CLI 才能收到任务；支持工具的管家仍读取最新目标作为事实来源。在项目页创建时沿用当前项目筛选，其他时候保存为个人事项。选择“交给管家”后先保存目标，再将目标 ID 和完整任务快照发送给唯一的 `concierge`。管家读取完整原文，整理标题、完成标准和下一步；没有充分依据时不猜测项目。管家存在则复用，不存在才准备一次，连续创建目标共用该准备过程。每个目标分别保留派发状态；发出消息仅证明 Herdr 接收，不代表负责人已启动或任务已完成。派发失败保留目标并提供重试。管家自行读取目标详情，创建目标 Tab、负责人或工人；Crewvane 不预设调度算法。

正在推进的新目标提供“我来处理”，通过 `goal.takeover` 转为人工推进，清除未发送的派发请求与仅由派发失败产生的介入项。迟到的发送回执必须按请求 ID 丢弃，不得把人工接管重新改为管家目标。保留人工查看 Herdr 现场、补充进展、编辑安排、提交成果和验收的能力；接管不终止或删除真实 Herdr 会话。

进行中的目标在详情显著位置提供自由消息框，用于追加新的要求、约束和想法。它通过 `goal.message` 保存完整原话与附件，并建立独立的待发送请求；消息入口本身不按关键词修改状态、下一步、等待对象或提醒。被路由给管家的消息必须实际送达，失败可重试。等待事项的到期卡只保留一个“告诉管家”输入框和一个“1 小时后提醒”次级动作；管家读取完整原话后，才通过结构化命令决定继续等待、恢复推进、验收或结束。高风险批准、交付验收和决定仍要求人的明确语义，并由 core 记录用户原话。Herdr 终端直聊和 `crewvane direct` 遵守同一边界。

管家只负责读取事项和规则、明确下一步、创建或复用独立负责人、转达任务与返工、跟进等待、核对交付记录并交接给人。不得亲自调查业务代码、产出或修改成果、执行目标命令和测试。负责人阻塞时通过澄清要求、调整分工或联系其他负责人协调恢复，不能由管家接手；协调后仍需人的决定时进入注意力。成果与真实检查由负责人提交，管家核对位置和记录是否齐备，缺失交回补齐，最终验收由人完成。

新建目标无需先建立项目。项目关联为可选整理与目录上下文，未选择时使用内置个人事项容器；CLI 的 `--project` 同样可省略。执行目标显示待分配负责人，登记现场后才显示负责人；连接是否可达由 Herdr 核实。未登记现场的活动目标超过一分钟启动宽限期，巡检先请管家补充分发；正在准备管家、等待他人或请求人的决定时不以未分配为故障。现场登记拒绝复用管家或其他未结束目标的 Tab、Pane 或 Agent。真实模型验收须从桌面创建两个目标，让管家自主创建两个独立负责人，不由测试脚本预先创建。

该职责边界同时写入初始身份说明、目标更新和巡检通知，避免已有管家沿用旧的“简单事项自己完成”规则。验收必须覆盖这三种消息入口，以及自定义 CLI 实际收到职责说明和目标通知。行为契约不等于第三方 CLI 的工具权限隔离，不得据此宣称技术上禁止了一切越权执行。

准备管家可以后台连接终端，但不得自动显示面板、关闭表单或抢走输入焦点。只有明确点击“找管家”或“回到现场”才显示；面板提供“隐藏终端”文字按钮，隐藏后保留会话与终端解析。打开新目标等表单时暂时隐藏终端，保留表单草稿；后台连接事件不能打断编辑。

管家给负责人发消息使用 Herdr 的 Agent 消息能力，例如：

```sh
herdr agent prompt <负责人名称> "<任务>" --wait
```

管家身份说明书必须要求：

- 先读项目规则；一个目标按需对应一个 Herdr Tab，保存实际 ID。
- 负责人创建后先保存真实 Herdr 现场，再发任务；发消息确认接收后即可继续统筹其他目标，不因一件长任务阻塞整个工作区。
- 负责人遇到问题时先自行解决；需要上级时先找管家，管家能解决则继续，只有管家不能解决才向人请求决定。
- 不催促人确认常规执行选择；合并或部署前调用 `goal ship`，任何九类高风险动作先调用 `goal risk`。
- 请求人决定前依赖决定账本去重；同一 PR 最多三轮审查，第四轮升级。
- 每次阶段变化通过 CLI 写回；提供下一步、实际进展、等待对象和提醒。
- 验收前写入真实成果和检查结果；不将 `herdr agent ... done` 当作目标完成。
- 不伪造 CLI 成功，不声称未运行的检查已通过。

## 6. CLI 协议

所有写操作通过同一份存储服务，使用进程锁与原子快照，不向 Agent 开放任意 shell 或任意路径写入。默认根为 `CREWVANE_WORKSPACE`，其次当前目录；桌面启动管家时显式提供工作区环境。

```text
crewvane status [--json]
crewvane attention [--json]
crewvane board [--new] [--once]
crewvane ask TEXT [--project ID]
crewvane goal list [--all] [--json]
crewvane goal show ID [--json]
crewvane goal message ID --text TEXT [--attachment PATH ...]
crewvane goal create --title TEXT --project ID [--description TEXT]
                     [--mode concierge|manual]
crewvane goal update ID [--title TEXT] [--description TEXT] [--next TEXT]
                        [--owner TEXT] [--status active|waiting] [--remind-at ISO]
crewvane goal progress ID --summary TEXT [--next TEXT] [--owner NAME]
crewvane goal wait ID --reason TEXT [--owner TEXT] [--remind-at ISO]
crewvane goal decide ID --question TEXT [--next TEXT]
crewvane goal risk ID --category CATEGORY --summary TEXT [--key KEY]
crewvane goal ship ID --operation merge|deploy --checks passed|failed
crewvane goal review ID --summary TEXT [--location TEXT] [--url URL]
                        [--check NAME::COMMAND::passed|failed::NOTE]
crewvane goal accept ID [--note TEXT]
crewvane goal complete ID --note TEXT
crewvane goal rework ID --note TEXT
crewvane goal drop ID --reason TEXT
crewvane goal remind ID --at ISO [--note TEXT]
crewvane goal resolve ID --note TEXT [--outcome approved|rejected]
crewvane session set ID [--workspace ID] [--tab ID] [--pane ID] [--agent NAME]
```

`--json` 输出可供 Agent 读取的结构化记录；默认输出简洁中文。写操作输出更新后的目标。所有时间使用 ISO 8601；ID 和路径按服务端验证。`goal accept` 只接受已有交付记录的目标；`goal complete` 用于用户明确要求结束、但没有正式交付审查的事项。两者都只结束 Crewvane 目标，不产生 Git 或部署副作用。`rework` 将目标退回 `active` 并清除待验收注意力；`resolve` 只解决决定 / 跟进，不代替成果验收。`goal ship` 只返回策略判断，不自行执行外部动作。

上线策略默认 `external-approval`。`goal ship` 先要求本地检查通过：默认档的合并和部署都等待人，`auto-merge-manual-deploy` 的部署等待人，`auto` 在检查通过后放行。人可在桌面修改项目策略；受管管家 CLI 没有策略修改入口。

人通过桌面或 Herdr 注意力面板批准/拒绝后，`goal.resolve` 保存原始回复、时间、来源、项目、目标和稳定动作键，并派生 `.crewvane/decisions.md` / `.crewvane/rejected.md`。`goal decide` 和 `goal risk` 先查账本，命中时不产生新的注意力。

`goal risk` 覆盖 `delete-data`、`stop-service`、`spend-money`、`external-message`、`product-direction`、`create-secret`、`rotate-secret`、`change-permissions`、`change-ship-policy`。这些动作即使处于 `auto` 项目也会先问人。同一目标默认最多三轮审查；第四轮返回 `intervention`，人在注意力面板允许后才增加一轮。

`ask` 与桌面单框新建共用 `goal.intake`，立即保存完整原文、附件和持久派发请求；桌面未运行或用户稍后启动时会补发。`goal message` 与 `direct` 是消息入口，只追加人的原话和附件，不覆盖下一步或改变状态；`direct` 不接受 `--next`。`progress`、`wait`、`review`、`decide` 等是 Agent 或受信任适配器在明确事实发生后使用的高级状态协议。`board` 是 Herdr 插件使用的同源终端 Pane：交互模式支持选择、补充/决定、等待跟进、继续推进、人工接管、验收、退回和聚焦负责人现场，`--once` 输出静态文本供测试和诊断。

管理人 CLI 时，每次通知由唯一案卷 scope 限定。受管 CLI 只可读取当前目标、查看精简 status，写入当前目标的 update、progress、wait、decide、risk、ship、accept、complete、rework、drop、resolve、remind、session；不得 list、attention、ask、message 或跨目标访问。这个应用层闸门不冒充操作系统文件沙箱。

等待目标的桌面操作是输入一句话交给管家，并保留 `goal.remind`（稍后提醒）作为独立次级动作。交给管家的 `goal.message` 清除已处理的到期注意力与旧提醒，但保持 `waiting` 和等待对象不变；个人事项的普通备注不清提醒；管家收到唯一 `feedback` 请求后，依据用户明确语义调用 `progress`、`wait`、`accept`、`complete`、`rework`、`drop`、`resolve` 或 `remind`。待发送消息持久化为带 ID 的 `dispatch` 请求，只有已送达才能标记 `sent`；失败可以重试，旧回执不能覆盖新请求。人工接管会取消派发；已移出且没有现场的个人记录允许显式恢复到暂存，不恢复任何 Agent 执行状态。

高级手动操作必须区分补充进展、编辑目标与提交成果。补充进展只写事实，不默认覆盖下一步；编辑目标调整安排但不提交验收；提交成果必须包含可核对成果与真实检查。等待中的直接操作与这些高级表单不能互相覆盖输入或改变原定安排。

## 7. 桌面实现边界

- `packages/core`：类型、默认值、校验、注意力派生、原子持久化与事件。
- `packages/orchestrator` 退役；不留下名为适配器但无调用方的旧代码。
- `apps/desktop/electron/main.ts`：可信文件选择器、Herdr / CLI 进程、通知和受约束 IPC。
- `apps/desktop/electron/herdr-plugin.ts`：随包插件部署、版本/源码校验、Herdr 注册与状态。
- `apps/desktop/herdr-plugin`：固定动作、Pane 清单和无 shell 拼接的启动脚本。
- `apps/desktop/electron/terminal-worker.ts`：独立 utility process 中连接 Herdr 的 PTY；主进程限制可执行文件、工作区和 IPC 输入。
- `apps/desktop/src`：React 界面；复用 Radix Dialog 与 Lucide，不自行实现另一套 Agent 协议。
- `cli`：用户 / Agent 共用的薄命令层，必须调用 core 服务而不是另写状态副本。
- `cli/src/board.ts`：Herdr 内注意力 Pane；只调用 core 和显式 Herdr CLI，不保存状态副本。

Electron 保持 `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`。渲染进程不能获得凭据、任意命令执行或任意本地文件读取。外部 URL 只允许明确的 `https:` 链接。CLI 安装通过应用内打包的独立可执行文件或自包含脚本实现，安装位置默认 `~/.local/bin/crewvane`，不覆盖非 Crewvane 文件。

## 8. 方案评审结论

评审按“是否减少上下文切换、是否只有一位管家、数据来源是否可信、Herdr 职责是否清晰、是否能验收成果”检查。

结论：通过，按以下约束开发：

1. 注意力只从明确目标记录、提醒和 Herdr 介入状态派生，不能以模型自言自语或终端空闲作为完成依据。
2. 桌面应用关闭窗口不清空目标或终止 Herdr 现场；应用重启可以恢复。
3. Herdr 不可用不阻塞纯记录功能，但创建管家 / 派工必须显示未就绪原因，不能假装已经派出。
4. 人的自由消息与机器状态命令严格分离；界面不从原话推断批准、验收或完成。
5. 项目筛选只过滤全局目标，不创建新管家。
6. CLI 和桌面并发写操作都要通过相同的锁；应用更新不能覆盖 Agent 同时写入的其他目标。
7. 验收卡必须展示实际交付与检查结果；验收通过、退回修改和放弃均留下时间线。

## 9. 验收标准

### 自动化

- core：新工作区默认值；并发写；锁恢复；非法状态；人工字段保留；四类注意力；通知去重；消息不改状态且按目标隔离；完整验收 / 退回 / 放弃闭环；三档上线策略；决定账本去重；九类高风险升级；第四轮审查拦截。
- CLI：真实进程调用目标创建、消息、进展、等待、决定、验收、完成；`direct` 拒绝进度别名；参数校验；JSON；工作区选择；桌面与 CLI 读写一致。
- Herdr adapter：使用测试替身验证固定 argv、真实 ID 解析、唯一管家、失效引用和错误传播；测试不得依赖当前用户的 Herdr 现场。
- Herdr 插件：验证清单版本与安装包一致、全部源码摘要、原子部署、幂等注册和错误状态；真实试用在隔离 Herdr 中打开 `dev.crewvane` Pane，验证注意力、一句话新目标、回到管家、现场关闭事件，并读取 `CREWVANE` 与注意力内容。
- 桌面 E2E：空状态、创建项目、单输入框交给管家、人工接管与迟到回执保护、侧边栏、项目筛选、四类注意力、上线策略、高风险决定、消息与附件、更新等待、验收卡、打开现场、设置、深浅主题与窄屏。
- 构建：typecheck、单元测试、renderer / Electron 构建均成功，无未处理运行时错误。

### 真实试用

在隔离的测试工作区和命名 Herdr Session 中，不控制用户现有会话：

1. 准备一位管家，核对 Session 中只有一个管家；关联两个项目及至少三个目标。
2. 管家为一个目标创建负责人，负责人通过 Herdr 收到消息；负责人用 CLI 汇报，桌面出现真实更新。
3. 设置一个短期等待提醒，等待期间不打扰，到期进入注意力且只通知一次。
4. 负责人提交交付，核对桌面展示成果、检查和 Herdr 现场；退回后重新提交，再验收通过。
5. 重启桌面，目标、引用和提醒保持；回到管家和目标现场可用。
6. 安装应用内 CLI 到临时 HOME，脱离源码目录运行读写命令，验证与桌面共享目标。
7. Herdr 缺失 / 启动失败 / 会话失效分别显示可行动的错误，不伪造成功。
8. 安装应用后不执行额外插件安装命令；Herdr 就绪时自动注册插件，并从隔离 Session 的真实 Pane 打开注意力控制台。

### 安装包

- 版本统一为本次发布版本；构建 DMG、ZIP、SHA256SUMS。
- 两种包都通过 `codesign --verify --deep --strict`、下载隔离属性检查、安装启动、CLI 安装和实际调用。
- 未配置 Developer ID 时明确保留未公证限制，不声称已通过公证。
- PR 包含开发说明、实现、测试、真实试用结果和已知限制。PR 验收后再单独决定是否发布 Release。

完成定义：上述功能不是静态原型；用户可以在桌面记录目标，在真实 Herdr 管家会话中继续，收到需要处理的事项，查看并验收实际成果，且安装包中的 CLI 可独立使用。
